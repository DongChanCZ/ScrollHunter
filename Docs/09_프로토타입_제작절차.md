### 3번이 가장 중요합니다 ★

Unity 6의 Universal 3D 템플릿은 **Input System 패키지**를 기본으로 씁니다.
이 상태에서 구형 `Input.GetKeyDown(KeyCode.Q)` 코드를 실행하면 **런타임 예외**가 납니다.
QWER 입력이 이 프로토타입의 전부이므로 1단계에서 바로 막힙니다.

| 선택지 | 내용 | 권장 |
|---|---|---|
| **Both** | 구형 Input API를 그대로 사용 가능 | ✅ 4일 프로토타입에는 이쪽 |
| Input System Package (New) | InputAction 에셋 설정 작업이 추가됨 | 정석이지만 느림 |

> `Both`로 두면 인계 사양의 "구형 Input API 사용" 규칙과 맞물려 AI가 헤매지 않습니다.
> Input System으로 가실 거라면 인계 사양의 해당 줄을 고치고, 프롬프트에 "InputAction으로 QWER를 바인딩해서 작성해줘"를 명시하세요.

### 확인

- 씬을 실행(▶)했을 때 에러 없이 빈 화면이 뜨면 준비 완료
- Project Settings에서 Active Input Handling이 `Both`인지 재확인

> **8번을 꼭 하세요.** 3단계에서 코드가 꼬였을 때 되돌아갈 지점이 없으면 하루가 날아갑니다.
> Git이 익숙하지 않으면 매 단계 시작 전에 프로젝트 폴더를 통째로 복사해 `ScrollHunter_D1` 식으로 두세요.

## 1단계 — 코스트 + 손패 순환 (반나절)

### ① 프롬프트

```
1단계만 만들어줘. 적은 아직 없어도 된다.

1. CostSystem: 초당 0.8 충전, 상한 10, 시작 3
   - 현재 코스트를 화면 좌하단에 숫자로 표시 (소수점 1자리)
2. SkillData (ScriptableObject): 이름, 코스트, 분류(Deal/Interrupt/Shield), 피해량(int), 타수, 캐스팅 시간
   - CreateAssetMenu로 에디터에서 생성 가능하게
3. DeckSystem: SkillData 8개 리스트를 받아 앞 4장을 손패, 나머지 4장을 대기열로 관리
   - QWER 키로 손패 사용
   - 코스트 부족 시 사용 실패 + 콘솔 로그
   - 사용한 카드는 덱 맨 아래로, 대기열 맨 앞이 그 슬롯에 진입
   - 슬롯 위치는 고정 (카드가 왼쪽으로 밀리지 않음)
4. 행동 잠금(GCD): 카드 사용 후 MAX(캐스팅 시간, 최소 GCD 0.4초) 동안 입력 무시
   - 최소 GCD(0.4)는 [SerializeField]로 노출
   - 잠금 중 손패 슬롯을 회색 처리하고 남은 시간을 소수점 1자리로 표시
   - 캐스팅 중 다른 카드 입력은 버퍼에 저장하지 말고 무시
5. UI: 손패 4칸에 카드 이름과 코스트 표시. 옆에 대기열 다음 1장을 회색으로 표시

만든 뒤, 내가 Unity에서 해야 할 작업을 순서대로 알려줘.
어떤 GameObject를 만들고 어떤 컴포넌트를 붙이고 무엇을 연결해야 하는지 구체적으로.
```

### ② 받은 뒤 내가 하는 일

| # | 작업 |
|---|---|
| 1 | 스크립트를 `_Project/Scripts/`에 `.cs` 파일로 저장 (클래스명 = 파일명) |
| 2 | 콘솔에 컴파일 에러가 없는지 확인 |
| 3 | `Data/` 폴더에서 우클릭 → Create → SkillData로 **테스트 카드 8개 생성** |
| 4 | 각 카드에 이름·코스트·분류 입력 (아래 표 참고) |
| 5 | 빈 GameObject `GameManager` 생성 → CostSystem, DeckSystem 컴포넌트 부착 |
| 6 | DeckSystem의 덱 리스트에 카드 8개를 순서대로 드래그 |
| 7 | Canvas에 손패 슬롯 4개 + 대기열 1개 + 코스트 텍스트 배치 후 연결 |

**테스트 카드 8장 (이 값으로 시작)**

| 슬롯 | 이름 | 분류 | 대상 | 코스트 | 피해량 | 타수 | 캐스팅 | 잠금 |
|---|---|---|---|---|---|---|---|---|
| 1 | 화염탄 | Deal | 단일 | 3 | 100 | 1 | 0.3 | 0.4 |
| 2 | 서리화살 | Deal | 단일 | 4 | 120 | 1 | 0.3 | 0.4 |
| 3 | 수정방패 | Shield | 자신 | 3 | — | — | 0.2 | 0.4 |
| 4 | 침묵 | Interrupt | 단일 | 4 | — | — | 0.2 | 0.4 |
| 5 | 연쇄번개 | Deal | 단일 | 6 | 50 | 3 | 1.0 | 1.0 |
| 6 | 폭발 | Deal | 단일 | 5 | 110 | 1 | 0.8 | 0.8 |
| 7 | 관통 | Deal | 단일 | 5 | 150 | 1 | 0.6 | 0.6 |
| 8 | 불기둥 | Deal | 단일 | 7 | 90 | 2 | 1.2 | 1.2 |

> **피해량은 기존 계수 × 100으로 환산한 값입니다.** 공격력 100이 곱해지던 것과 결과가 같으므로 밸런스 변화가 없습니다.
> 광역 카드는 아직 없습니다. 5~8일차에 스킬 14종을 확정할 때 딜 8장을 단일 4 / 광역 4로 나누세요.

> 「잠금」은 `MAX(캐스팅, 최소 GCD 0.4)`으로 자동 계산됩니다. 입력할 필요 없이 확인용입니다.
> **대응 카드(수정방패·침묵)를 3·4번 슬롯에 배치**했습니다. 킵 플레이를 전제로 한 배치입니다.

> 이 구성은 밸런스시트 `덱시뮬` 시트에서 검증한 것입니다. 총 코스트 37, 1사이클 46초.
> 대응 카드가 손패(3·4번 슬롯)에 있으므로 **킵이 가능합니다.** 쓰지 않으면 계속 남습니다.
> 대신 실질 손패가 2칸이 되어, 매 순간 고를 수 있는 딜 카드가 줄어듭니다. 이것이 킵의 대가입니다.
>
> 방어 카드를 한 번 쓰면 덱 맨 아래(8번)로 가고, 다시 손에 오려면 앞 4장을 더 써야 합니다.
> 코스트 기준 약 **25초**. 전투가 40초이므로 **전투당 1~2회**만 쓸 수 있습니다.
> 즉 "지금 이 빨강에 방어를 쓸 것인가"가 무게 있는 결정이 됩니다.

### ③ 확인 방법

- ▶ 실행 → 코스트가 3에서 올라가는가
- Q를 누르면 화염탄이 사라지고 대기열의 폭발이 1번 슬롯에 들어오는가
- 코스트가 부족할 때 키를 누르면 실패 로그가 뜨는가
- 8장을 다 쓰면 첫 카드가 다시 돌아오는가
- **불기둥(캐스팅 1.2초)을 쓴 직후 1.2초 동안 다른 키가 안 먹는가**
- **화염탄(즉발)을 쓴 직후에는 0.4초만 잠기는가**
- **코스트를 10까지 모은 뒤 저가 카드 3장을 약 1.2초에 연속으로 쓸 수 있는가**

## 2단계 — 적과 캐스팅 바 (반나절)

### ① 프롬프트

```
2단계. 적을 추가한다.

1. EnemyData (ScriptableObject): 이름, HP, 방어력, 캐스팅 시간, 담당 색상(Green/Orange/Red), 피해량
   - 공격력 필드는 두지 말 것
2. Enemy: 캐스팅 시간만큼 대기 → 발동 → 1초 휴식 → 반복
   - 적 본체는 Capsule 하나면 충분
3. 캐스팅 바 UI: 적 위에 진행률 바. 담당 색상으로 채워짐
   - 3색은 인스펙터에서 Color로 지정 가능하게
   - 캐스팅 중인 스킬 이름도 바 위에 표시
4. EnemyManager: 적 3체를 관리. 적끼리 발동이 겹치지 않게 최소 0.5초 간격 강제
5. Player: HP 500, 방어력 20. 적 공격 발동 시 피해 계산 후 적용
   - 피해 = Mathf.FloorToInt( 적 피해량 * 100f / (플레이어 방어력 + 100f) + 0.5f )
   - Mathf.RoundToInt는 은행가 반올림이라 쓰지 말 것
   - 곱셈을 먼저 할 것. (1 - def/(def+100)) 형태는 오차로 25가 24가 된다
   - 검증값: 30 → 25, 40 → 33, 150 → 125
   - HP 0이면 콘솔에 "패배" 출력 후 일시정지

아직 차단/방어는 만들지 마. 지금은 그냥 맞기만 하면 된다.
Unity에서 내가 해야 할 배치 작업도 순서대로 알려줘.
```

| # | 작업 |
|---|---|

| 2 | 캐스팅 시간: 초록 2.5초 / 주황 3.0초 / 빨강 4.0초 |
| 3 | HP는 셋 다 300, 피해량은 초록 30 / 주황 40 / 빨강 150 |
| 4 | Capsule 3개를 화면에 나란히 배치 후 Enemy 컴포넌트 부착 |
| 5 | 캐스팅 바 UI 프리팹 만들어 적마다 연결 |
| 6 | 카메라 각도 조정 — **적 3체의 캐스팅 바가 한눈에 보이게** |

### ③ 확인 방법

- 세 캐스팅 바가 서로 다른 색으로 채워지는가
- 발동이 동시에 터지지 않는가 (0.5초 이상 벌어지는가)
- 빨강 한 방에 HP가 크게 깎이는가
- 아무것도 안 하면 약 몇 초 만에 죽는가 → **이 값을 기록해두세요.** 3단계 비교 기준입니다

## 3단계 — 차단 + 방어도 (1일, 핵심)

### ① 프롬프트

```
3단계. 여기가 이 프로토타입의 핵심이다.

1. 차단(Interrupt) 카드: 캐스팅 중인 적을 대상으로 사용
   - 성공: 캐스팅 취소 + 해당 적 4.0초 경직
   - 주황 캐스팅에만 유효. 빨강에 쓰면 실패 (코스트는 소모, 로그 출력)
   - 캐스팅 중이 아닌 적에게는 사용 불가 (코스트 소모 없음, 실패음 대신 로그)
2. 방어도(Shield): Shield 카드 사용 시 플레이어에게 방어도 120 부여
   - 피해는 방어도에서 먼저 차감, 초과분만 HP에
   - 방어도는 전투 종료까지 유지 (시간 감소 없음)
   - 화면에 방어도 수치를 HP 옆에 표시
3. 타겟팅: 마우스 클릭 또는 좌우 방향키로 적 선택. 선택된 적 위에 조준 마커 표시
   - 전투 시작 시 1번 적 자동 지정. 타겟 사망 시 자동으로 다음 생존 적으로 이동
   - Deal/단일과 Interrupt는 타겟에게 적용. Deal/광역은 적 전체, 타겟 무관
   - 차단 카드는 타겟이 캐스팅 중이 아니면 슬롯 비활성 (입력 불가)
   - 타겟이 빨강 캐스팅 중이면 활성이되 사용 시 실패, 코스트는 소모
4. 적 사망 처리: HP 0이면 비활성화. 전원 사망 시 콘솔에 "승리"

카드 사용 시마다 콘솔에 [시간 / 카드명 / 코스트 / 대상 / 결과]를 출력해줘.
```

### ② 받은 뒤 내가 하는 일

| # | 작업 |
|---|---|
| 1 | 수정방패 카드의 방어도 부여량을 120으로 설정 |
| 2 | 침묵 카드가 Interrupt 분류인지 확인 |
| 3 | **최소 5회 이상 직접 플레이** |
| 4 | 플레이하면서 느낀 점을 `07_개발일지`에 메모 |

### ③ 적 방어력을 정할 때 확인할 것

3단계에서 적에게 방어력을 부여하면 플레이어 → 적 피해에도 소수가 생깁니다.

- 카드 8장의 `피해량 × 타수 × 100 / (적 방어력 + 100)`을 찍어보고, 크리티컬 1.8배 경우도 함께 확인
- **밸런스시트 `스킬` 시트의 기대 피해(소수)와 게임 내 실제 피해(정수)가 일치하는지** 대조
- 시트는 소수를 그대로 들고 있고 게임은 정수로 떨어뜨리므로, 오차가 크면 시트 쪽에 반올림을 반영할 것

### ④ 이때 관찰할 것 (중요)

플레이하면서 아래를 **의식적으로** 확인하세요. 나중에 회상하면 부정확해집니다.

- [ ] 적의 캐스팅 바를 실제로 보고 있는가, 아니면 내 손패만 보는가
- [ ] 주황이 뜨면 "침묵이 손에 있나"를 확인하게 되는가
- [ ] 침묵이 대기열에 있을 때 앞 카드를 질러서 끌어오게 되는가 ← **이게 나오면 설계 성공**
- [ ] 코스트를 아끼려고 참는 순간이 있는가
- [ ] 빨강이 뜰 때 긴장되는가

## 4단계 — 계측 (반나절)

### ① 프롬프트

```
4단계. 재미 검증을 위한 계측을 넣어줘.

전투 종료(승리/패배) 시 콘솔에 요약 출력:
- 총 전투 시간(초)
- 카드별 사용 횟수
- 차단 시도 횟수 / 성공 횟수
- 방어 카드 사용 횟수
- 코스트 부족으로 실패한 입력 횟수
- 코스트가 상한 10에 도달해 소멸한 총량
- "필요 카드를 끌어오기 위한 사용"으로 추정되는 횟수
  (= 코스트 5 이상 보유 상태에서 계수가 가장 낮은 카드를 쓴 경우)

복사해서 붙여넣기 쉽게 한 덩어리 텍스트로 출력해줘.
```

### ② 판정 기준

**5회 플레이한 평균**으로 판단합니다.

| 지표 | 정상 | 이상 신호 | 대응 |
|---|---|---|---|
| 차단 + 방어 사용 | 전투당 2회 이상 | 0~1회 | 대응 카드 코스트를 낮추거나, 적 위협을 키울 것 |
| 코스트 소멸량 | 0에 가까움 | 많음 | 회복 속도를 0.6으로 낮출 것 |
| 코스트 부족 실패 | 가끔 | 매우 잦음 | 회복 속도를 1.0으로 올릴 것 |
| 카드별 사용 편차 | 고름 | 특정 카드만 | 엑셀 `스킬` 시트의 코스트당 기대 피해 확인 |
| 전투 시간 | 40±10초 | 크게 벗어남 | 적 HP 조정 |
| 끌어오기 사용 | 1회 이상 | 0회 | 대응 카드를 덱 뒤쪽에 배치했는지 확인 |

> **차단·방어 사용이 0에 가까우면 이번 재설계의 핵심 가설이 틀린 것입니다.**
> 그 경우 5일차에 방향을 수정하세요. 이 시점이 마지막 분기점입니다.

## 막혔을 때 쓰는 프롬프트

### 컴파일 에러

```
아래 에러가 난다. 콘솔 로그 전문이다.

[에러 전문을 자르지 말고 그대로 붙여넣기]

관련 스크립트는 다음과 같다.
[해당 .cs 파일 전문]
```

> **에러 메시지를 요약하지 마세요.** AI는 스택 트레이스의 줄 번호와 타입명을 읽습니다.

### 동작이 이상할 때

```
의도한 동작: [무엇이 일어나야 하는지]
실제 동작: [무엇이 일어났는지]
재현 방법: [어떻게 하면 재현되는지]
관련 스크립트: [파일 전문]

원인 후보를 먼저 나열하고, 어떤 로그를 찍어 확인할지 알려줘. 바로 고치지 말고.
```

> "바로 고치지 말고"가 중요합니다. 원인 파악 없이 수정하면 다른 곳이 깨집니다.

### 수치를 바꾸고 싶을 때

```
[수치]를 [값]으로 바꾸고 싶다. 인스펙터에서 바꿀 수 있나?
없다면 [SerializeField]로 노출시켜줘.
```

> 이 요청이 자주 나온다면 애초에 하드코딩된 것입니다. 노출시켜두면 이후 밸런싱이 훨씬 빨라집니다.

### Unity 6에서 API나 메뉴가 다를 때

```
Unity 6.3 (6000.3.18f1)을 쓰고 있다.
알려준 [API명 / 메뉴 경로]가 내 버전에는 없거나 Obsolete 경고가 뜬다.

실제 화면: [본 것을 그대로 적기]

Unity 6 기준으로 맞는 방법을 알려줘.
```

> Unity 6 계열은 2022 LTS와 메뉴 구성·패키지 구조가 꽤 달라졌습니다. AI가 구버전 기준으로 답하는 경우가 흔하니, **버전을 명시하고 실제로 본 화면을 적어주는 것**이 가장 빠릅니다.

### 입력이 아예 안 먹을 때

```
QWER 키 입력이 전혀 반응하지 않는다.
Project Settings → Player → Active Input Handling은 [현재 설정값]이다.
[스크립트 전문]
```

> 십중팔구 Active Input Handling 문제입니다. `Both`인지 먼저 확인하세요.
