# 09. 프로토타입 제작 절차 (4일)

> **Scroll Hunter** 전투 프로토타입. 목표는 하나 — **적의 캐스팅을 읽고 코스트를 배분하는 것이 재미있는가.**
> 이 문서는 "내가 직접 하는 일"과 "AI에게 시키는 일"을 구분해 순서대로 정리한 것입니다.
> 코드 세션에서는 `08_코드세션_인계사양`의 사양 블록을 먼저 붙인 뒤 여기 프롬프트를 사용하세요.

> 현재 실행: 시작 → 튜토리얼 → 완료/스킵 후 편성 → A+B → C → A+B+C → 보스. 보스는 [10 A34](10_결정사항_로그.md#boss-phases-20260930), 포션 3/3은 [A46](10_결정사항_로그.md#potion-three-20261007), [현재 확인](07_개발일지.md#d15-close) 참조. 원본 [10 A32](10_결정사항_로그.md#tutorial-implementation-20260930), 확인·한계 [07 D-11](07_개발일지.md#d11-tutorial). 아래 과거 B→C→B+C 검사와 현재 구성을 구분한다.

> 최신 작업은 [07 D-16 계승](07_개발일지.md#d16-inheritance). 10/7 마감은 [D-15](07_개발일지.md#d15-close), 남은 직접 플레이·빌드는 [D-16](07_개발일지.md#d16-followup). 아래 기본 수치 확인은 계승 없는 상태 기준이다.

## 패배 후 계승 확인 (2026-10-08)

원본 [10 C](10_결정사항_로그.md#inheritance-20261008), 적용·검사 [07](07_개발일지.md#d16-inheritance). Battle에 연결돼 있어 추가 배치 없음. 재배치는 Edit 모드의 `Tools > Scroll Hunter > Apply Inheritance UI` 사용. 기존 UI를 삭제하지 않는다.

1. 일반 전투 보상으로 스킬이나 패시브를 얻고 이후 전투에서 패배. 연출이 끝난 뒤 「계승 선택」을 누른다.
2. 이번 런에서 얻은 후보만 보이는지 확인. 교체해 뺀 스킬은 포함, 시작 시 보유분·치유의 스크롤·계승 상한 도달 항목은 제외한다.
3. 스킬 선택 → 영구 시작 덱에서 교체 자리 선택 → 중앙 「확인」 → 시작 화면. 선택 전 확인은 어둡게 비활성화, 선택 후 활성화. 확인 전 덱·계승 목록은 유지. 다시 선택·오른쪽 스킵은 미확정 선택 취소. 패시브는 선택 후 시작 화면.
4. 「계승 정보」에서 자리·스택 확인. 다음 런의 튜토리얼은 기본 편성, 완료/스킵 후 본편부터 계승이 적용되는지 본다. 전투를 넘겨도 패시브가 중복 적용되지 않아야 한다.
5. Stop 후 새 Play에서 계승 유지 확인. 별도 빌드의 종료·재실행도 후속 확인한다. 같은 PC의 에디터와 빌드는 회사/제품 설정이 같으면 저장 경로를 공유한다.
6. 계승 초기화 → 취소하면 유지, 확인하면 기본 상태. 후보 없는 패배와 PS02만 얻은 패배는 선택 없이 시작 화면으로 돌아간다.
7. Play 시작 화면이 뜬 뒤 `Check Inheritance (Play)`. 임시 저장으로 선택·중복·상한·파일 재읽기·손상·저장 실패·초기화를 검사한다. 실제 계승 저장은 변경하지 않는다. 자연 플레이 중에는 실행하지 않는다.
8. 기본 수치 회귀는 `Check Tutorial Combat Regression (Play)` 사용. 계승을 분리한 임시 저장으로 검사한다. 이전 개별 검사는 기본 능력치 전제이므로 계승이 있는 런의 실패를 곧바로 게임 오류로 판정하지 않는다.

기록: 계승 전/후 목록, 선택 이유, 다음 런 덱·능력치, 정지·배속, 오류 여부. 새 빌드·직접 2런의 체감은 함수 검사와 구분한다.

## 배경 배치 확인 (2026-10-07)

사양 [10 A45](10_결정사항_로그.md#backgrounds-20261007), 파일·조정 위치 [06](06_에셋_파이프라인.md#background-assets-20261007), 결과·한계 [07](07_개발일지.md#d15-background-placement).

4. 실제 창에서 보스 동굴은 어둡고 적은 식별되는지, 갈색 적과 배경이 분리되는지 확인. 적·타겟 마커·게이지·HUD·스킬 연출이 소품에 가려지지 않아야 함. 배경은 화면비에 맞춰 가장자리가 일부 잘림.
5. 위치는 Battle의 `BattleEnvironment` 자식에서 조정. 전투 코드·조명·원본 FBX를 함께 바꾸지 않음. 새 빌드 성능·직접 플레이는 별도 기록.
6. [일반 맵 가시성 후속](10_결정사항_로그.md#outdoor-readability-20261007): 깡패부터 3체 전투까지 몸·무기 뒤 나무/바위가 겹치는지 확인. 일반 바위만 Outdoor 재질 사용, 보스 배경은 기존값 유지. 후속 검사·화면은 [07](07_개발일지.md#d15-outdoor-readability).

## 적 모델 Unity 적용·동작 확인 (2026-10-02)

10/7 후속: 우두머리 대기·시전에서 턱이 얼굴과 함께 도는지 확인. 초록 차단 피격 중 왼손이 몸통을 가로지르지 않고, 복귀 때 다시 검을 잡아야 한다. `Check Enemy Death Ending (Play)`는 튜토리얼 사망·스킵·도중 재시작 포함. 작업본·검사 한계는 [07](07_개발일지.md#d15-tutorial-leader-fix).

사용 파일은 [06](06_에셋_파이프라인.md#enemy-model-pipeline), 현재 6단계 순서는 [07 D-13](07_개발일지.md#d13-model-animation), 결과·남은 문제는 [궁병 수정](07_개발일지.md#d13-archer-fix)·[4단계](07_개발일지.md#d13-enemy-rigs)·[10/6 보정·전투 연결](07_개발일지.md#d14-model-fixes). 아래는 반입·씬·무기·동작의 재검사 절차이며 전 항목 통과 기록이 아니다. 10/6부터 5종 동작이 전투에 연결돼 있다.

1. 근거자료 원본은 읽기만 한다. Unity는 `Assets/_Project/Models/Enemies/`의 복사본을 쓰고 원본 FBX를 다시 내보내지 않는다.
2. 캐릭터 모델 FBX 임포트 설정 유지: Humanoid·Create From This Model, Import Animation 끔, Bake Axis Conversion 켬, `material_0` → 전용 머티리얼 재매핑, Normal PNG는 노멀맵 형식. 별도 Mixamo 동작 FBX에는 Import Animation을 켠다.
3. `Tools > Scroll Hunter > Check Enemy Models` 실행. 원본 해시·FBX 내장 PNG·보정 PNG 일치, 아바타·필수 뼈 15·손가락 30, 클립 없음, 머티리얼·텍스처 연결, 발끝 -Z·크기를 본다. 모델·텍스처를 바꾸면 스크립트의 원본 경로 표도 고친다.
4. 화면은 MCP 등에서 `EnemyModelChecks.Capture(경로, 자세, yaw, …)`. 미리보기 장면에서만 그려 씬이 바뀌지 않는다. 자세 `down`·`bend`는 근육 값 시험이며 애니메이션 품질 검사가 아니다.
5. 보정 텍스처는 깡패 정수리·궁병 손바닥 근접 화면을 근거자료의 보정 전후 화면과 비교한다.
6. Blender 검사 통과를 Unity 아바타 통과로, 아바타 통과를 무기·애니메이션·게임 거리 통과로 보지 않는다.
7. **궁병 활·화살(10/2):** 무기를 고칠 때는 `근거자료/2026-10-02_궁병무기/make_bow_arrow.py`를 Blender에서 `-- <근거자료 폴더> <Assets/_Project/Models/Weapons/Archer>`로 다시 실행. FBX·텍스처를 덮어쓰며 Unity 재질·재매핑·프리팹 연결은 유지된다. 활대 자식 empty는 축 변환이 틀어지므로 만들지 않는다.
8. 장착 확인: 프리팹 `ENM_Archer_ORG_v01`의 `LeftHand/BowSocket`·`RightHand/ArrowSocket`. 손 뼈 축척 100·소켓 축척 0.01 유지. 현재 Mixamo의 대기·당김·조준·사망 자세에서 손·무기·옷 겹침을 본다. 이전 근육 값 시험 자세만으로 통과 판정하지 않는다.
9. 시위·발사: 현재 BowRig는 Animator의 `BowDraw`를 읽으므로 `Draw` 속성만 바꿔 검사하지 않는다. 조준 후 Animator의 `Release` 트리거와 `BowRig.Release(목표, 시간)`를 함께 실행한다. 손 화살 숨김·비행 후 삭제·시위 복귀를 보고, 복귀 뒤 다음 당김 전까지 시위가 다시 당겨지지 않는지 확인한다(10/2 수정, 발사 후 `BowDraw`가 0.05 아래로 내려올 때까지 무시). 수동 `Animator.Update`나 `EditorApplication.Step` 반복은 한 번의 실행 안에서 프레임이 진행되지 않으므로, 전투를 시작해 게임 시간을 흐르게 한 뒤 편집기 업데이트 콜백으로 실프레임 값을 기록한다. `ReadyArrow`로 손 화살 복귀, 시간 0에서 정지도 확인. 화살에는 충돌·피해가 없어야 한다.
10. 동작 재생성은 수정할 때만 한다. `Tools > Scroll Hunter > Build Archer Animations`는 직접 제작 클립·컨트롤러를 갱신하며, Mixamo 클립이 있으면 컨트롤러는 Mixamo를 사용한다. 직접 제작본으로 돌아가려면 무기 소켓도 다시 맞춘다. 읽기 검토에서는 빌더를 실행하지 않는다.
11. Mixamo 원본은 `근거자료/2026-10-02_Mixamo원본/`, Unity 복사본은 `Animations/Archer/Mixamo/`. `Apply Archer Mixamo Clips`는 회전·소켓·시위 곡선·컨트롤러를 갱신하고 저장 전 FBX 원래 자세를 복원한다(10/2 수정). 방향은 Play의 Animator로 확인한다(미리보기 샘플은 회전 보정 미반영). 궁병 컨트롤러의 피격 전환은 10/2 직접 수정본이며, `Build Archer Animations`를 다시 돌려도 같은 구조가 된다.
12. 동작 확인: Play에서 실제 한 프레임 이상 진행한 뒤 Animator를 검사한다. Draw→Aim→Release→Idle, Hit 끼어들기·복귀, 반복 뒤 자세·루트 위치 유지, Death를 본다. `DrawSpeed = 당김 클립 길이 / 적 시전 시간`. 현재 Mixamo는 약 1.068초이므로 시전 2.5초면 약 0.427이다. 전환 시간을 포함해 발동 시점과 대조하고 적 시전 시간은 바꾸지 않는다. 수동 `Animator.Update` 검사와 실제 프레임·손 조작 검사를 구분한다.

1. Git 변경·씬 저장 상태·최신 문서를 확인하고 현재 화면과 실제 실행 환경을 보존한다. 화면 기준은 [10 A27 후속](10_결정사항_로그.md#display-mode-20261001). Player Settings와 기존 해상도 강제 코드도 대조한다. 다른 작업자의 미완료 변경을 덮어쓰지 않는다.
2. 기존 UI 자료·CREDITS를 확인한다. 부족한 자료만 [06 무료 UI 절차](06_에셋_파이프라인.md#free-ui-assets-20261001)에 따라 선정한다.
3. 전투 HUD·능력치 창·피격 피드백을 먼저 적용하고 화면을 남긴다. 확정 방향 안의 크기·색·잔상 시험값을 조정한 뒤 전체 화면으로 확장한다.
4. 시작·튜토리얼·정보창·편성·보상·결과와 적 게이지의 재질·대비·여백을 맞춘다. 기존 스킬 프레임·정사각형 아이콘·폰트·설명 정렬을 유지한다.
5. 아래 확인 후 변경 파일·출처·전후 화면·검사 방법·미확인을 07 D-12에 기록한다. 새 사양이 필요하면 자동 채택하지 않는다.

### 확인 항목
1. [10 A27 후속](10_결정사항_로그.md#display-mode-20261001)에 따라 UI 기준 화면과 실제 모니터 전체화면에서 겹침·잘림·장식 과밀을 확인한다. 작은 창은 회귀 확인용으로 구분한다. 긴 스킬 설명·두 줄 이름·패시브 10종의 이름/효과 시작 위치와 하단 안내를 비교하고 검사 해상도를 기록한다.

3. 연속 피격·최대 HP 증가·전투 전환·재시작을 확인한다. 잔상·피해 숫자가 이전 전투에서 남거나 최대치 증가를 회복으로 표시하면 실패.
4. 코스트 충전·소모·상한, 포션 사용·0개·PS01 획득, 능력치·패시브 중첩·재시작 초기화를 실제 값과 대조한다. 기본 상한·포션 개수를 UI에 고정하지 않는다.
5. 코스트 부족·차단 잠김·행동 잠금·기절·튜토리얼 지정 스킬 음영과 적 캐스팅 3색을 구분한다. 시전 바와 코스트를 혼동하지 않는지 본다.
6. 능력치 창 열기/닫기·기존 수동 정지·0.5배속, 카드 좌클릭·정보창·순서 드래그/저장/취소·보상 선택/스킵을 확인한다. 새 UI 클릭이 뒤의 적·스킬로 통과하면 실패.
7. 최신 [시작 준비](#battle-ready-checks)·[보스 차단](#boss-checks)·튜토리얼 스킵도 회귀 확인한다. 기능 호출·실제 프레임·직접 손 조작·새 빌드는 각각 구분해 07에 기록한다.
8. 새 실행 파일에서 창 테두리 없이 모니터에 맞춰 표시되는지, 이전 창모드 설정이 남지 않았는지, 화면의 버튼·손패 클릭 위치가 맞는지 확인한다. 에디터 화면만으로 전체화면 적용 통과를 판정하지 않는다.
9. [10 A37 후속](10_결정사항_로그.md#resource-hud-20261001)의 조작 버튼 외곽이 시작 버튼과 같은지 확인한다. 편성 저장/취소·보상 스킵/뒤로·다음 전투/재시작·정지/배속/능력치·런타임 생성 튜토리얼 스킵을 포함한다. 기본·마우스 오버·눌림·비활성 구분과 클릭 위치, 저장 왼쪽/취소 오른쪽을 확인. 적용 결과는 [07](07_개발일지.md#d12-common-buttons).
10. 시작 제목의 새 글꼴과 잘림을 확인한다. 제목용 SDF는 정적 글리프라 제목 문구를 바꾸면 누락 글자를 확인·추가한다. 전투 알림은 원복된 기존 폰트인지 대조. 원본은 10 A37 후속, 확인은 [07](07_개발일지.md#d12-fonts).

## 빨강 피격·표시 크기·패배 연출 확인 (2026-10-07)

사양 [10 A44](10_결정사항_로그.md#red-hit-defeat-feedback-20261007), 결과·미확인 [07](07_개발일지.md#d15-hit-ending). 추가 씬 배치 없음. 화면·HUD 흔들림은 Play 때 자동 연결, UI 확대도 실행 때 적용한다.

1. 자동 검사 전 마법사 직행을 끄고 Play. `Tools > Scroll Hunter > Check Ending Feedback (Play)` 실행. 피격 조건·원위치 복구·숫자 크기·입력 차단·재시작 검사이며 런을 초기화한다.
2. `Check Ending Feedback Frames (Play)` 실행. `EndingFeedbackChecks.FrameResult`에서 디엔드 1/0.5배속·매직미사일·우두머리·궁병 패배 결과 확인. 시전·HP를 지정한 실제 프레임 검사이며 자연 플레이는 아니다.
3. 직접 Play에서 방어도 없음/있음/이번 피격으로 소진·무적을 나눠 빨강 피격 확인. 배경·적·HP·카드 UI가 함께 흔들리고 끝나면 원위치로 복구되는지 확인. 화면 가장자리 빈틈·게이지 위치 어긋남도 확인.
4. 방어도 아이콘·숫자, **내 HP바 위 피해 숫자**를 확인. 적 위 피해 숫자·차단 문구·회복 숫자는 기존 크기여야 한다.
5. 디엔드로 HP 0이 되어도 확산·걷힘이 보이고 이후 결과가 뜨는지 확인. 대기 중 카드·포션·충전·추가 공격 없음, 재시작 후 잔여 폭발·카메라 오프셋 없음 확인.
6. 전투 중 수동 정지·0.5배속, 승리 연출도 확인. 기능 검사·직접 플레이·새 빌드를 구분해 07에 남긴다.
7. `Check HUD (Play)`로 흡수 표시도 검사. 직접 확인은 전부 흡수 / 방어도 정확히 소진·HP 유지 / 일부 흡수를 나눈다. 전부 흡수만 바운스, 일부 흡수는 방패 움직임 없이 흡수·HP 숫자가 각각 표시돼야 한다.

## 튜토리얼 확인 (2026-09-30)

Battle 씬에 연결돼 있어 추가 배치 없음. 기존 실행 파일에는 이번 변경이 없다. 직접 확인 결과는 07 D-11에 기록한다.

1. Play → 게임 시작. 편성 없이 깡패 1체와 코스트 안내. 화면에 학습 번호가 없고 안내창 우측 하단에 `Space`만 보이는지 확인. Enter(숫자패드 포함)·Space·좌클릭 각각으로 설명이 넘어가는지 확인한다.
2. Q 안내에서는 `Space` 표시가 숨겨지고 다른 슬롯은 음영·입력 불가. Q 또는 해당 아이콘 사용 시 시간 재개·카드 순환. 다음 Q 카드도 잠겨야 한다.
3. 초록→주황→빨강 순서 확인. 주황 절반에서 설명 → E 안내 → 침묵 입력. 차단 경직 뒤 중간 초록 없이 빨강 → 절반에서 설명 → R 안내 → 매직아머 입력. 효과는 기존 시전 시간 뒤에 나오고, R 이후 일반 GCD가 끝나면 자유 사용.
4. 빨강 피격 뒤 포션 안내에서 Shift는 아무 동작 없음. 안내를 넘기면 처치 문구가 나오는지 확인. 처치 안내도 넘긴 뒤 시간이 흐를 때 Shift 사용. 포션 사용은 필수 아님. 먼저 적 HP가 0이었다면 처치 안내 없이 완료 안내로 넘어가야 한다.
5. 적 처치 → 쓰러짐 끝까지 재생 → 완료 안내. 사망 모션 중 카드·포션·안내 넘김 불가. 편성은 숨겨지고 완료 안내에서 기다려도 전환되지 않아야 한다. 엔터·스페이스바·좌클릭으로 확인 → 배치 안내 → 안내 닫기 → 순서 변경·드래그 → 저장/취소 → 전투 시작. A+B 진입 시 HP·포션 초기화와 편집한 순서를 확인. 이후 C·A+B+C는 정상 이월·보상 확인.
6. 다른 실행에서는 중간 사망과 우측 상단 스킵 확인. 사망 시 완료 학습·적 HP는 유지하며 플레이어 상태·기본 손패를 복구. 스킵은 보상·완료·7단계 안내 없이 편성 확인으로 이동.
7. 안내 넘김 클릭이 카드나 전투 시작 버튼까지 누르지 않는지, 안내 중 코스트·시전·기절·적 공격이 멈추는지 확인. 종료·스킵·재도전 뒤 이전 시전/유지 효과가 남으면 실패.

내부 검사(실제 손 입력과 구분):

- `Tools > Scroll Hunter > Check Tutorial (Play)`: 현재 저장 편성·학습·실패 경로의 함수/버튼 이벤트 검사. 완료 후 새 튜토리얼로 복구.

## 빨강 반감 확인 (2026-09-29)

원본 [10 A33](10_결정사항_로그.md#red-shield-20260929), 검사 범위 [07 D-10](07_개발일지.md#d10-red-shield). **저장된 Battle 씬에 반영.** 아래는 재확인 절차이며 기능 검사와 실제 손 조작은 구분한다. 이전 절차의 C 피해·무입력 전멸 기록은 A33 전 기준이다.

## 패시브 보상 실행·확인 (2026-09-23)

사양은 [10 A28](10_결정사항_로그.md#all-passives-20260923), 전체 구현은 [07 D-09](07_개발일지.md#d09-all-passives), 현재 기본 포션은 [10 A35](10_결정사항_로그.md#potion-two-20260930), 후보 표시 검사는 [07 D-11](07_개발일지.md#d11-passive-reward-card). 구버전 빌드는 [위 절](#windowed-build)과 구분한다. Battle 씬 연결 완료, 추가 배치 없음.

1. 현재 Battle 씬을 Play → 「게임 시작」 → 튜토리얼 완료/스킵 → 편성 → 「전투 시작」 → 3초 준비 후 A+B. 구버전 실행 파일로 최신 사양을 판정하지 않는다.
2. A+B 승리 후 보상 확인. 카드 후보와 패시브 후보가 함께 표시된다. 패시브를 좌클릭하면 교체 없이 바로 적용되고 「다음 전투」가 열린다.
3. 화면 하단의 현재 능력치·이름·스택 확인. 다음 전투에서 효과·스택이 유지되고 덱은 그대로인지 본다. 카드 보상을 고르면 기존 8장 중 1장 교체 절차를 따른다.
4. 후속 보상에서 같은 패시브를 고르면 스택이 올라간다. 현재 런은 A+B·C·A+B+C 후 보상 총 3회. 자연 획득으로 확인할 수 없는 높은 PS 상한은 아래 내부 검사로 구분한다. 다음 런에는 임시 패시브를 지우고 영구 계승만 적용한다. 계승 없는 상태는 기본 능력치로 돌아간다.
5. Console의 보상 획득 로그와 다음 전투 요약의 시작 조건을 대조한다. 계측은 오늘 변경분 적용 후 진행하며, 빌드·배속·정지 사용·보상 선택과 의도를 함께 기록한다.
6. 내부 검사: Play에서 **Tools → Scroll Hunter → Check All Passives (Play)**. 기존 2종 회귀는 **Check Passive Rewards (Play)**. 강제 승리·추가 보상 기회로 획득·상한·이월·재시작을 확인하고 첫 전투로 복귀한다. 실제 손 조작·자연 플레이·밸런스 검증을 대신하지 않으며, 사용자 계측 도중 실행하지 않는다.

7. 전투 중 HP가 줄었을 때 **Shift** 사용. 시전·채널링은 계속되고 포션 개수·HP가 바뀌는지 확인. 최대 HP 500·현재 HP 100이면 250이 되는지 확인한다(회복 기준 10 A8·A28). 다음 전투에 남은 개수가 이월되고 다음 런 본편은 영구 계승을 반영한 최대 개수로 시작한다. 정지·기절·만피·0개·전투 밖에서는 소모하지 않는다.
8. 방어도·차단 강화는 카드 툴팁과 효과 로그의 적용값을 비교한다. 최대 HP·코스트 상한만 올리면 현재값은 유지. PS01은 최대치와 남은 개수가 각각 1 늘어야 한다. 전부 사용한 0/2에서 획득하면 1/3, 사용 전 2/2에서 획득하면 3/3. 재시작 후 2/2 확인(10 A35).
9. PS10은 자연 플레이에서 나오지 않아도 실패가 아니다. 1% 경계·상한은 내부 검사로 확인한다. 포션 사용 로그·실회복량은 카드 사용과 별도로 기록한다.

### 배치·설정 위치

- Systems/BattleFlow의 Reward Pool: 카드 6종과 PS01~10 효과 에셋. `Card Choice Limit`·`Passive Choice Limit`의 합은 연결된 선택 버튼 수 이내로 둔다. 현재 연결값은 10 A28을 따른다.
- 효과 에셋: `Assets/_Project/Data/ScrollHunter/PS*.asset`. `Stat`·`Amount`·`Additional Bonuses`·`Max Stacks`와 설명을 함께 관리한다. 설명에는 조건·주의 문구만 적는다. 보상 후보의 효과 줄은 `Stat`·`Amount`에서 만들고 문구는 BattleRewardUI `Passive Stat Formats`에서 수정한다(10 A28 보상 후보 표시). PS10만 `Rare Reward`·`Offer Chance`를 사용. 방어도 배율 증가는 0.2=20%, 치명타 확률은 5=5%p. 같은 PS는 같은 원본 에셋을 재사용한다.
- Canvas/PassiveStatus: 하단 현황 표시. BattleFlow의 `Passive Text`에 연결됨. 값·문구는 에셋과 인스펙터에서 수정한다.
- `StatRewardEffect`는 현재 10종의 증가·즉시 회복·복합 효과를 지원한다. 기본값은 CostSystem/Player에 남고 런 증가분만 별도 적용한다.
- Player의 `Base Potion Capacity`·`Potion Heal Fraction`·두 입력 키가 포션 설정. Canvas/PotionStatus를 CombatUI의 `Potion Text`에 연결했다. 추가 수동 배치 없음.

## 크리티컬 실행·확인 (2026-09-23)

사양은 [10 A25](10_결정사항_로그.md#critical-hits-20260923), 구현 확인·패시브 검토는 [07 D-09](07_개발일지.md#d09-critical-passive-review) 참조. Battle 씬에 연결했으므로 추가 배치 없음.

1. Battle 씬의 Player에서 `Critical Chance`·`Critical Multiplier`를 확인하고 Play → 「게임 시작」. 기본값은 10 A25·T21을 따른다.
2. 파이어볼의 일반/치명타 숫자·적 HP 감소를 비교한다. 현재 방어력 0에서는 일반 30, 치명타 45. 치명타는 연한 빨강·검정 테두리로 표시된다.
3. 매직 커터·광역·채널링은 같은 카드 사용 안에서 일반/치명타가 섞일 수 있다. 제압은 피해만 증폭되며 차단 성공 여부·경직은 별도 판정이다.
4. Console의 타격 로그와 최종 요약을 대조한다. 사망 뒤 잔여 연출은 유효 타격·치명타 집계에서 빠져야 한다. 요약은 마지막 행동 뒤에 한 번 출력된다.
5. Play 상태의 `Tools > Scroll Hunter > Check Critical Hits (Play)`로 저장 카드 11종·독립 추첨·반올림·중단·표시·집계를 검사한다. 검사 후 설정·난수를 복원하고 첫 전투로 돌아간다. 실제 손 조작·밸런스 검증을 대신하지 않는다.

결정적인 확인이 필요하면 **Play 중에만** 확률을 0%/100%로 바꿔 비교하고 Stop한다. 저장 기본값을 시험값으로 덮어쓰지 않는다. 이전 `Builds/2026-09-23_StartScreen`은 크리티컬 구현 전 빌드다. 9/23 포션 빌드도 이후 변경을 포함하지 않는다. 최신 확인은 현재 에디터 또는 새로 만든 빌드에서 진행한다.

5. 배치 완료: `Canvas/StartScreen`의 배경·제목·조작 안내·StartButton과 Systems/BattleFlow의 `Start Panel`·`Start Button` 참조를 연결했다. 추가 배치 불필요. 문구·배치는 해당 TMP·RectTransform에서 수정.

7. 현재는 시작 화면 「게임 종료」 또는 Alt+F4. 종료·옵션 메뉴는 [10/8 후속](#main-menu-checks)으로 추가했다.

## 시작 메뉴·옵션 확인 (2026-10-08)

## 보상 선택·덱 교체 실행·확인 (2026-09-22)

사양은 [10 A23](10_결정사항_로그.md#reward-flow-20260922), 구현·검사·화면 근거는 [07 D-08](07_개발일지.md#d08-reward-flow). Battle 씬 연결 완료, 추가 배치 불필요.

1. Battle 씬 Play → 「게임 시작」 → 튜토리얼 완료/스킵 → 편성 → 「전투 시작」 → 3초 준비 → A+B 승리. 보상 화면에서 카드 정보를 읽고 하나를 좌클릭.
2. 현재 덱 8장 중 교체할 카드 좌클릭 → 중앙 「확인」. 선택 전 확인은 어둡게 비활성화, 선택 후 활성화. 다른 자리를 누르면 음영만 이동하고 덱은 확인 뒤에 바뀌어야 한다. 1~4번은 시작 손패, 5~8번은 대기열. 「보상 다시 선택」·오른쪽 「보상 스킵」은 미확정 선택 취소. [10/8 검사·화면](07_개발일지.md#d16-replacement-confirmation).
3. 편성을 확인하고 「다음 전투」. 필요하면 [순서 편집](#deck-order-checks)을 먼저 진행. 최종 저장 위치에 새 카드가 반영되고, 코스트를 모아 QWER 또는 좌클릭으로 사용할 수 있는지 확인. 전투 번호·이월 HP·보상 선택도 기록.
4. C·A+B+C 후에도 보상을 확인한다. 현재 덱에 있는 카드는 후보에서 제외되어야 한다. 교체 취소로 재추첨되지 않아야 하며, 스킵한 경우와 구분한다. 보스 승리·패배 후 재시작하면 최초 편성으로 돌아오는지 확인.
5. 기능 검사: Play 중 **Tools → Scroll Hunter → Check Rewards (Play)**. 임시 HP·손패·적 상태와 Editor 전용 효과를 사용하며 종료 시 원래 보상 풀·시작 덱·첫 전투로 복귀. 실측 도중 실행하지 않음. 함수·버튼 이벤트 검사이며 실제 손 입력을 대신하지 않음.

### 보상 구성·패시브 연결

1. Play를 끄고 Systems → `BattleFlow`의 `Reward Pool` 확인. 현재 카드 6종은 Card만, 패시브 10종은 Effect만 연결. 후보 수·설정 위치는 위 패시브 절 참조.
2. 카드 추가는 SkillData를 만들고 보상 풀 Card에 연결. 새 종류를 넣기 전에 효과 경로·설명·검사를 갖출 것. 현재 카드 후보 제외는 같은 SkillData 참조 기준이므로 동일 카드의 복제 에셋을 다른 종으로 넣지 않음.
3. 다른 효과를 추가할 때는 `RunRewardEffect`를 상속한 ScriptableObject에 `Apply(Player, CostSystem)`·`Remove()`·필요한 `CanOffer(...)`를 구현. 항목의 Card는 비우고 Effect만 연결. 카드/효과를 둘 다 넣거나 둘 다 비우면 후보 제외.
4. Apply는 획득별 복제본에서 실행됨. Remove는 부분 적용 실패·재시작·런 폐기에서도 자신이 준 상태만 해제해야 함. 전투 시작에 초기화되는 방어도·현재 코스트와 런 지속 효과를 구분하고, PS별 스택 상한은 BattleFlow가 원본 에셋 기준으로 후보 생성·선택 때 검사. 추가 조건만 CanOffer에서 검사. 수치만 입력하면 실제 패시브가 생기는 구조는 아니며 개별 효과 구현·검사는 별도.

### 구성을 바꿔 별도 시험할 때

1. Play를 끄고 Systems → `BattleFlow` → `Encounters`에서 각 전투의 Label·Enemies를 설정한다. 3체 구성은 가장 강한 적을 `Center Enemy`로 지정한다. A·B·C는 사용자 확정대로 C를 지정한다. 지정 누락·구성에 없는 중앙 적은 시작 오류로 알린다.
2. EnemyManager의 `Formation Center`·`Side Offset`으로 배치 중심과 간격을 조절할 수 있다. 적 바와 타겟 표시는 자동으로 따라간다. 전투 도중 사망해도 생존 적 위치는 유지한다.
3. 기존 A+B+C 광역 비교를 다시 할 때는 Play 전에 해당 시험용 구성과 DeckSystem의 `Starting Deck`을 맞춘다. 카드 교체는 아래 광역 시험 절차를 따른다. 현재 3전투 시연을 같은 조건의 재측정으로 사용하지 않는다. 임시 구성을 저장했다면 시험 후 승인된 시연 구성을 복구한다.

### 기능 검사 다시 실행하기

3. `Canvas/DamageNumbers`에서 색·표시 시간·상승 거리·위치 조절. `Horizontal Spread`는 X 무작위 범위이며 0이면 고정. `Interrupt Text / Color / Size Multiplier`로 차단 문구·색·숫자 대비 크기 조절. `NumberTemplate`은 비활성 유지하며 폰트·숫자 크기 조절. 테두리는 연결된 Maplestory Damage Outline 머티리얼에서 조절.
4. Play 중 **Tools → Scroll Hunter → Check Damage Numbers (Play)**로 피해·차단 표시와 정리 검사. 치명타는 검사에서 직접 전달하며 자연 발생·확률 검증이 아님. 검사 후 첫 전투로 복귀.
5. 정지·재개, 적 처치, 승리·패배 후 재시작에서 숫자·차단 문구가 남지 않는지 확인. 기능 검사는 실제 마우스·키보드 조작 검증과 구분.

## 후속 채널링 — 개별 효과 연결·확인 (2026-09-21)

공통 사양은 [10 A18](10_결정사항_로그.md#channeling-definition), 이번 구현 확인은 [07 D-07](07_개발일지.md#d07-channeling) 참조. 공통 기반만 만들었던 당시와 달리 현재 시작 덱에는 채널링 2종이 연결됨. 위 시작 덱 절 참조.

카드별 대상·후딜·무효화 피해 기준은 [10 스킬 검토 반영](10_결정사항_로그.md#skill-review-20260922) 참조. 해당 효과의 구현·확인은 별도로 진행.

### 개별 채널링 스킬을 만들 때

1. `ChannelEffect`를 상속한 효과 스크립트에서 `Begin`(시작), `Tick`(진행), `End`(정리)를 작성한다. `ChannelContext`에서 카드·플레이어·적 관리자를 읽는다. 기본 클래스 자체는 추상형이므로 에셋으로 만들지 않는다.
2. 필요한 수치와 표시 설명은 해당 효과의 직렬화 필드에 둔다. 효과 클래스에 `CreateAssetMenu`를 붙여 에셋을 만든다. 설명에 계산값이 필요하면 `Describe(SkillData)`가 현재 수치를 읽도록 작성한다.
3. 스킬 에셋에서 `Activation = Channeling`, `Cost`, `Cast Time`(채널링 지속시간), `Channel Effect`를 설정한다. 효과 분류·대상은 실제 기능과 맞춘다. `damage / hitCount / shieldAmount` 값은 채널링에 자동 적용되지 않는다. 해당 기능이 필요하면 연결 효과가 명시적으로 읽어 처리해야 한다.
4. 시험할 때 기존 덱 한 장과 새 스킬을 교체한다. **기본 채널링 기능만을 위한 GameObject·컴포넌트·씬 참조 추가는 없다.** 개별 효과가 요구하는 추가 참조는 그 효과를 만들 때 연결한다.
5. Play 후 시작 즉시 효과, 진행 중 다른 카드 거절, 정지·재개, 정상 종료·기절·전투 종료 시 유지 효과 정리를 확인한다. 종료 후 원치 않는 피해·상태 잔류가 없는지 본다. 실제 코스트·카드 소모는 1회여야 한다.
6. 손패 hover 설명과 시전 바의 채널링 이름·시간을 확인한다. 빈 효과 또는 잘못된 시간은 「설정 필요」 상태로 사용이 거절되어야 한다.

새로운 무적·면역 등은 수치 입력만으로 생기지 않는다. 해당 효과와 피격·상태이상 처리의 연결 구현이 필요하다. 공통 기반과 시작 덱의 피해 채널링 구현이 무적·면역 구현 완료를 뜻하지 않는다.

### 공통 기능 회귀 검사

- Play를 끈 뒤 Unity 메뉴 **Tools → Scroll Hunter → Check Channeling**을 실행한다.
- `ChannelingChecks.Run()`은 임시 씬·메모리 스킬·검사용 효과로 일반 시전과 채널링을 검사한다. 저장 씬·실제 덱·기존 스킬 에셋은 변경하지 않고 원래 활성 씬과 배속을 복구한다.
- 이 검사는 지정한 시간만큼 내부 진행 함수를 호출하는 기능 검사다. 실제 키보드/마우스 입력이나 개별 스킬 밸런스·자연 플레이의 검증을 대신하지 않는다.

## 후속 광역 1종 시험 절차 (초기 3단계와 구분)

목적은 여러 적의 HP를 함께 깎는 선택과 위협적 적의 집중 처치, 긴 시전의 위험 사이에 판단이 생기는지 보는 것이다. 260918의 광역 부재·캐스팅 읽기 관찰에서 이어졌으며 결과 개선을 미리 단정하지 않는다.

시험값·사용자 승인 예외·비교 피해표는 [10 광역 시험 한정값](10_결정사항_로그.md#aoe-trial-values), 실제 구현과 제출 결과는 [07 D-07](07_개발일지.md#d07-aoe-results), 오늘 할 일은 [07 D-07 목록](07_개발일지.md#d07-todo)을 따른다.

### 덱 교체·복구 방법

교체 지점은 **한 칸**뿐이다.

1. Unity에서 `Assets/_Project/Scenes/Battle.unity`를 연다
2. Hierarchy에서 `Systems` 선택
3. Inspector의 **DeckSystem → Starting Deck → Element 7**(8번째, 맨 아래)
4. 시험용으로 바꿀 때: `Skill_FlamePillar_AoeTest` 를 드래그하거나 원형 아이콘으로 선택
5. 대조용으로 되돌릴 때: `Skill_FlamePillar` 로 되돌린다
6. 씬 저장(Ctrl+S)

덱 8장·등록 순서·나머지 7장·적 구성·`minGcd 0.4`·`interruptStagger 2.5`는 어느 쪽이든 그대로다.
DeckSystem 컴포넌트를 지웠다 다시 붙이면 코드 기본값 `interruptStagger = 4f`가 적용돼 씬 값 2.5가 조용히 사라진다. **컴포넌트를 재생성하지 말 것.**

불기둥은 덱 8번째라 초기 손패(화염탄·서리화살·수정방패·침묵)가 아니라 **대기열 맨 뒤**다. 손패에 들어오려면 카드를 4번 써야 한다. 광역을 못 쓴 회차가 있으면 시전 길이 때문인지 덱 진입 지연 때문인지 구분해서 기록해야 한다.

### 사전 조건과 실제 수행의 차이

아래는 사전 절차다. 구현 당시 함수 호출 확인은 [07 D-07 구현 확인](07_개발일지.md#d07-aoe-implementation), 이후 제출된 실플레이 4건과 입력 경로의 부분 확인은 [광역 1종 비교계측](07_개발일지.md#d07-aoe-results) 참조. 좌클릭의 모든 거절 조건·정지 조작 경로까지 검증 완료한 것은 아니다.

1. **입력·기능 확인:** `09`의 후속 UI 실제 입력 확인을 먼저 마친다. 이후 광역이 타겟과 무관하게 생존 적 전체에 한 번씩 적용되는지, 시전 완료 전 피해가 없는지, 기절 취소·종료 후 피해 방지가 유지되는지 확인한다. 이 확인 전투는 플레이 비교 횟수에서 제외한다.
2. **첫 비교는 A+B+C(사용자 선택):** 현재 불기둥 덱과 광역 불기둥 덱을 각각 2회씩, 대조→광역→광역→대조 순으로 배치한다. 4회는 최대 압박 조건에서 문제를 찾는 탐색이며 통계적 결론을 내리는 표본이 아니다. 2초 시전 기회를 잡기 어려울 수 있으므로 광역을 못 쓴 원인도 기록한다.
3. **추가 비교는 미결정:** 첫 4회에서 사용 기회가 부족하거나 압박 때문에 원인을 구분하기 어렵다면 B+C 또는 C 단독 시험을 별도로 검토한다. 지금은 추가 회차를 확정하지 않는다. 서로 다른 적 구성의 승률을 직접 섞지 않는다.

계획상 고정 조건: 같은 코드·UI 버전, 카드 교체 외 덱 순서·임시 카드값 동일, 적 구성별 수치·배치 동일, 새 전투·HP 500·시작 코스트 3·방어도 0, 1배속, 포션 없음. 조작 방식도 묶음 안에서 동일하게 사용한다. 정보는 전투 전에 읽고 비교 중 수동 일시정지를 쓰지 않는 조건을 제안했다.

**실제 수행과의 차이:** 사용자는 피해 계산용 툴팁 확인에 필요하면 수동 정지를 사용했다고 답했다. 회차별 사용 여부·횟수는 미확인이다. 1회차는 좌클릭·키보드 혼용, 2~4회차는 성공 입력 로그상 키보드 경로다. 따라서 무정지·동일 조작 조건을 충족한 시험으로 표시하지 않는다. 수치와 판단 장면은 정보 확인을 포함한 탐색 자료로 사용한다.

처치 순서·카드 사용 순서는 강제하지 않는다. 그것이 관찰할 판단이다. 2026-09-17~18 기록은 배경 자료로만 사용하고 현재 UI에서 대조 회차를 새로 측정한다.

광역 시험을 끝내거나 중단할 경우의 복구 대상은 **시험 직전의 임시 순환 상태**다. 불기둥 단일·3코스트·피해39×2·시전1.2초 등 사전 저장값으로 복구하며, 정식 원복값인 7코스트·90×2피해로 임의 복구하지 않는다. 실제 적용 전 저장값을 다시 확인한다.

### 기록·판정 방법

기존 계측: 승패, 게임 내 전투 시간, 남은 HP, 처치 수, 카드별 사용 횟수·순서, 차단 시도·성공, 방어 실제 흡수, 코스트 부족·상한 손실.

이번에 수동으로 추가할 핵심 관찰:

| 회차·시각 | 적 생존 수·각 HP·위협 캐스팅 | 손패·코스트 | 선택과 이유 | 결과 |
|---|---|---|---|---|
| 제출 1~4회차 | [광역 1종 비교계측](07_개발일지.md#d07-aoe-results) §2·§4 참조 | 같은 문서의 로그 재구성 | §5 플레이어 답변과 해석 | 원문은 해당 문서에서 연결 |

광역을 쓰지 않은 장면도 기록한다. 손패에 없었는지, 코스트가 부족했는지, 시전이 위험했는지, 먼저 처치할 적이 있었는지 구분한다. 시전 시작·완료 시 생존 수가 다르면 둘 다 적는다. 현재 합산 피해 로그만으로 대상별 실효 피해나 과잉 피해가 자동 집계된다고 가정하지 않는다. 확인할 수 없는 값은 미확인으로 남긴다.

판정 질문:

- 적이 여러 체일 때 광역을 고르되, 한 체를 빨리 처치해야 하거나 상대 발동이 임박하면 단일·대응·대기로 바꾸는 장면이 있었는가?
- 총피해·승률뿐 아니라 첫 처치 시점, HP 보존, 시전 중 피격·취소가 어떻게 달라졌는가?
- 계속 광역만 썼거나 전혀 쓰지 않았다면 위력·접근성·표시·시전 위험 중 어떤 원인인가?

생존 시간 증가나 광역 사용 횟수만으로 성공을 판정하지 않는다. 이 시험안은 2체에서 단일과 피해 합계가 같은 안이 아니다. 높은 총피해만으로 실제 처치 효율이나 적정 밸런스를 확정하지 않는다. 결과에 따라 유지·시험값 한 항목 조정·추가 관찰 중 다음 행동을 정한다.

## 3단계 — 차단 + 방어도 (1일, 핵심)

### ① 프롬프트

```
3단계. 여기가 이 프로토타입의 핵심이다.

침묵 코스트 2, 시전 0.2초. 입력 시 캐스팅 중이어야 사용 가능하고, 효과 적용 시에도 초록·주황 캐스팅 중이어야 성공한다. 먼저 발동하면 실패·경직 없음. 코스트·카드는 실패해도 소모된다.
모든 카드는 유효 입력 수락 즉시 같은 슬롯에 다음 카드가 들어온다. 효과는 시전 완료 시 적용하며, 기절 취소 시 추가 순환하지 않는다.

1. 차단(Interrupt) 카드: 캐스팅 중인 적을 대상으로 사용
   - 성공: 캐스팅 취소 + 해당 적 2.5초 경직
   - 초록·주황 캐스팅에 유효. 빨강에 쓰면 실패 (코스트는 소모, 로그 출력)
   - 캐스팅 중이 아닌 적에게는 사용 불가 (코스트 소모 없음, 실패음 대신 로그)
2. 방어도(Shield): Shield 카드 사용 시 플레이어에게 방어도 120 부여
   - 피해는 방어도에서 먼저 차감, 초과분만 HP에
   - 방어도는 전투 종료까지 유지 (시간 감소 없음)
   - 화면에 방어도 수치를 HP 옆에 표시
3. 타겟팅: 마우스 클릭 또는 좌우 방향키로 적 선택. 선택된 적 위에 조준 마커 표시
   - 전투 시작 시 1번 적 자동 지정. 타겟 사망 시 자동으로 다음 생존 적으로 이동
   - Deal/단일과 Interrupt는 타겟에게 적용. Deal/광역은 적 전체, 타겟 무관
   - 차단 카드는 타겟이 캐스팅 중이 아니면 슬롯 비활성 (입력 불가)
   - 타겟이 빨강 캐스팅 중이면 활성이되 사용 시 실패, 코스트는 소모
4. 적 사망 처리: HP 0이면 비활성화. 전원 사망 시 콘솔에 "승리"

카드 사용 시마다 콘솔에 [시간 / 카드명 / 코스트 / 대상 / 결과]를 출력해줘.
```

### ② 받은 뒤 내가 하는 일

| # | 작업 |
|---|---|
| 1 | 수정방패 카드의 방어도 부여량을 120으로 설정 |
| 2 | 침묵 카드가 Interrupt 분류인지 확인 |
| 3 | **최소 5회 이상 직접 플레이** |
| 4 | 플레이하면서 느낀 점을 `07_개발일지`에 메모 |

### ③ 적 방어력을 정할 때 확인할 것

3단계에서 적에게 방어력을 부여하면 플레이어 → 적 피해에도 소수가 생깁니다.

- 카드 8장의 `피해량 × 타수 × 100 / (적 방어력 + 100)`을 찍어보고, 크리티컬 1.5배 경우도 함께 확인 (10 T21, 추첨·배율 구현 후 검증)
- **밸런스시트 `스킬` 시트의 기대 피해(소수)와 게임 내 실제 피해(정수)가 일치하는지** 대조
- 시트는 소수를 그대로 들고 있고 게임은 정수로 떨어뜨리므로, 오차가 크면 시트 쪽에 반올림을 반영할 것

## 4단계 — 계측 (반나절)

목적은 **적의 위협을 보고 공격·차단·방어에 코스트를 배분하는 판단이 발생하는지** 확인하는 것이다. 생존 시간 하나나 카드 사용 횟수만으로 성공·실패를 판정하지 않는다.

### ① 시작 전 확인 및 고정 조건

### ③ 계측 자체의 확인

- 카드 한 번 사용 시 사용 횟수 1회. 효과 적용 때 다시 증가하지 않는지 확인.
- 성공한 침묵은 시도 1·성공 1, 빨강 대상 실패는 시도 1·성공 0인지 확인.
- 비캐스팅 대상의 거절 입력과 잠금 중 입력이 사용·차단 시도·코스트 부족 횟수에 섞이지 않는지 확인.

## 막혔을 때 쓰는 프롬프트

### 컴파일 에러

```
아래 에러가 난다. 콘솔 로그 전문이다.

[에러 전문을 자르지 말고 그대로 붙여넣기]

관련 스크립트는 다음과 같다.
[해당 .cs 파일 전문]
```

> **에러 메시지를 요약하지 마세요.** AI는 스택 트레이스의 줄 번호와 타입명을 읽습니다.

### 동작이 이상할 때

```
의도한 동작: [무엇이 일어나야 하는지]
실제 동작: [무엇이 일어났는지]
재현 방법: [어떻게 하면 재현되는지]
관련 스크립트: [파일 전문]

원인 후보를 먼저 나열하고, 어떤 로그를 찍어 확인할지 알려줘. 바로 고치지 말고.
```

> "바로 고치지 말고"가 중요합니다. 원인 파악 없이 수정하면 다른 곳이 깨집니다.

### 수치를 바꾸고 싶을 때

```
[수치]를 [값]으로 바꾸고 싶다. 인스펙터에서 바꿀 수 있나?
없다면 [SerializeField]로 노출시켜줘.
```

> 이 요청이 자주 나온다면 애초에 하드코딩된 것입니다. 노출시켜두면 이후 밸런싱이 훨씬 빨라집니다.

### Unity 6에서 API나 메뉴가 다를 때

```
Unity 6.3 (6000.3.18f1)을 쓰고 있다.
알려준 [API명 / 메뉴 경로]가 내 버전에는 없거나 Obsolete 경고가 뜬다.

실제 화면: [본 것을 그대로 적기]

Unity 6 기준으로 맞는 방법을 알려줘.
```

> Unity 6 계열은 2022 LTS와 메뉴 구성·패키지 구조가 꽤 달라졌습니다. AI가 구버전 기준으로 답하는 경우가 흔하니, **버전을 명시하고 실제로 본 화면을 적어주는 것**이 가장 빠릅니다.

### 입력이 아예 안 먹을 때

```
QWER 키 입력이 전혀 반응하지 않는다.
Project Settings → Player → Active Input Handling은 [현재 설정값]이다.
[스크립트 전문]
```

> 십중팔구 Active Input Handling 문제입니다. `Both`인지 먼저 확인하세요.
