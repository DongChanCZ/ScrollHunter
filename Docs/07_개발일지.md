##### ⓒ 끌어오기는 발생하지만 방향이 반대다

기획 상정: 「🟠 주황이 뜬다 → 침묵이 손에 없다 → 앞 카드를 써서 **침묵을 끌어온다**」
실제 발생: 「침묵(코스트 2)을 값싼 순환 카드로 써서 **수정방패를 끌어온다**」 — 7회차 #6→#7, 8회차 #1→#2

플레이어 증언: 차단 성공의 경직은 **부가효과**로 느껴진다.
가설(「필요한 카드를 끌어오려고 코스트를 쓴다」)은 **성립한다.** 다만 끌어오는 쪽과 끌려오는 쪽이 뒤바뀌었다.

##### ⓓ 기절 페널티가 의도만큼 무겁지 않다

플레이어는 **카드를 잃었다는 느낌을 받지 않는다.** 카드 코스트가 전반적으로 높아 어차피 코스트를 기다리는 중이라
손패 접근이 병목이 아니기 때문이다. 11회 중 기절 취소는 **1회**였다. 그 회차의 최종 결과가 비슷해도 취소의 영향이 없었다고 단정할 수 없다.

##### 다음 행동 — 「추가 시험」을 택한다

`09` ⑥의 세 선택지 중 **유지 + 추가 시험 1건**을 권한다. **수치 변경은 권하지 않는다.**

- 회복량은 유지한다. 적은 상한 손실과 후반 부족 입력은 소비 양상이며, 적정 회복량을 입증하지는 않는다
- ⓐ·ⓑ의 원인은 아직 확정하지 않는다. 카드 수치·손패 접근·적 구성·학습의 영향을 구분한다
- 약 5회씩의 비교는 원인 탐색용이며 확정적 통계가 아니다 (`09` ⑥)

**추가 시험 제안: 적 구성만 바꿔 같은 3묶음을 다시 돌린다.**
목적은 ⓐ 의 검증이다 — 조건이 달라지면 선택도 달라지는가, 아니면 여전히 한 풀이로 수렴하는가.
카드·적 개별 수치, 덱 순서, 배치 위치, 시작 조건은 유지한다. 구성 변경안은 시험 전 기록하고, 씬 변경과 추가 시험은 아직 실행하지 않았다.

- 결과와 사용 순서가 달라지면 → 어떤 위협 때문에 선택을 바꿨는지 관찰 메모로 확인한다. 결과 차이만으로 가설 성공을 확정하지 않는다
- 전략이 반복되면 → 다른 선택의 가능성과 시험 조건을 먼저 확인한다. 난수·비대칭 정보 도입이 필요하다고 바로 결론 내리지 않는다

> 위 해석은 11회 표본에 기반한 초기 판단이다. 수치·사양은 아무것도 바꾸지 않았다.
> 변경을 결정하면 `10` 결정 로그와 관련 문서를 함께 갱신한다 (`09` 4단계 ⑥).

##### 남은 확인과 후속 근거

- **실제 입력:** 제출 1회차에 좌클릭 사용 경로 4건, 전 회차에 키보드 사용 경로가 있다. 정지 사용은 사용자 진술로 확인했으나 우클릭·버튼 중 어느 경로인지와 모든 비활성 조건은 미확인이다. 상세는 [광역 1종 비교계측](07_개발일지.md#d07-aoe-results) §6 참조.
- **연속 플레이에서의 체감·실측:** 제출 로그 4건과 플레이어 답변을 [광역 1종 비교계측](07_개발일지.md#d07-aoe-results)에 정리했다. 전체 시도 수·회차별 정지 이력은 미확인이며 정식 채택과 구분한다.
- **대상별 실효 피해·과잉 피해:** 자동 집계는 없다. 제출 4건은 적 HP와 입력·효과 순서를 함께 재구성해 실효 피해·과잉 피해를 별도 계산했다([광역 1종 비교계측](07_개발일지.md#d07-aoe-results) §3). 광역 합계 한 줄만으로 일반적인 모든 장면을 분해할 수 있다는 뜻은 아니다.
- **다른 화면비·해상도에서의 정보창 표시**
- 정보창 피해 문구가 「대상당」인지 「총합」인지 문면으로 구분되지 않는다. 광역 카드에서 `30 × 2`가 대상당 값이라는 점은 10의 시험 한정값에서 확인할 수 있다 — 문구 변경은 이번 범위 밖으로 두었다

##### 구현 종료 당시 상태

- **당시 저장 덱: 대조용(원본 단일 불기둥).** Element 7 = Skill_FlamePillar
- 덱 8장·등록 순서·나머지 7장 그대로, `minGcd 0.4` / `interruptStagger 2.5` 그대로
- 적 구성 A+B+C 3체 모두 활성, `EnemyManager.enemies` 직렬화 목록은 원래대로 비어 있음(활성 오브젝트 자동 수집)
- 플레이어 `currentHp 500` / `resetHpOnStart` 켜짐, `Time.timeScale 1`
- Play 모드 종료, 씬 저장 완료(dirty 없음)
- 시험용 에셋은 삭제하지 않고 보존

이것은 구현 작업 종료 당시의 기록이다. 이후 제출 로그와 최신 저장 씬 확인은 [광역 1종 비교계측](07_개발일지.md#d07-aoe-results) §1·§7 참조. 이 절로 현재 Unity 실행 중 덱을 단정하지 않는다.

#### 광역 비교계측·플레이어 답변 (2026-09-21)

**상태: 사용자가 제출한 플레이 로그 4건·플레이어 답변 5항목·1차 해석 정리 완료. 전체 플레이 횟수와 회차별 정지 이력은 미확인. 수동 정지를 포함한 탐색 기록이며 정식 밸런스 채택·시험값 변경·추가 구현은 미결정이다.**

이 절의 회차는 전체 플레이의 연속 번호가 아니라 **이 대화에 제출한 순서**다. 시험값은 [10 시험 한정값](10_결정사항_로그.md#aoe-trial-values), 계획·복구 기준은 [09 시험 절차](09_프로토타입_제작절차.md#aoe-trial-procedure), 구현 당시 함수 호출 검증은 [구현검증](07_개발일지.md#d07-aoe-implementation)에 있다. 이 절에는 실제 제출 결과와 플레이 의도를 모은다. 이전 UI·적 구성별 계측과 한 묶음으로 합치지 않는다.

##### 1. 근거와 실제 조건

- 제출 순서: A+B+C 단일 불기둥 → 광역 → 광역 → 단일, 각 덱 2건. 카드 이름·피해·입력과 결과 시각으로 구분했다.
- 사용자는 피해 계산을 위해 툴팁이 필요하면 수동 정지를 사용했다고 답했다. **회차별 정지 여부·횟수·시간은 미확인**이다. 계획의 무정지 조건을 충족했다고 기록하지 않는다.
- 현재 저장 코드에서 배속 전환·포션 사용 기능은 미구현이며 전투는 1배속으로 시작한다. 각 과거 실행의 코드·UI 버전 동일성이나 외부 배속 조작 여부까지 로그가 증명하는 것은 아니다. 실제 배속을 사용했다는 진술은 없다.
- 성공 카드 사용의 호출 스택: 1회차 좌클릭 경로 4회·키보드 경로 18회, 2/3/4회차 키보드 경로 9/20/23회. QWER 표기 자체가 장치를 뜻하는 것은 아니다.
- 전투 시간은 게임 내 시간이다. 수동 정지 시간은 빠지므로 실제 소요 시간·판단에 쓴 시간으로 해석하지 않는다.
- 사용자는 광역 뒤 방어 준비 지연으로 패배한 경험을 설명하면서 “내가 올린 계측은 승리했을때의 플레이를 올림”이라고 덧붙였다. **제출 2회차 원문은 27.52초 패배**다. 기록의 승패는 그대로 두며, 미공유 시도 수·승패·선별 제출 여부와 해당 실패 장면은 추가 확인이 필요하다.
- 전체 시도 수가 없으므로 제출 4건을 전체 승률이나 패배 확률로 환산하지 않는다. 모든 회차가 조건을 통제한 연속 시험이었다고도 가정하지 않는다.

##### 3. 피해·HP 재계산

로그의 카드 피해에는 남은 적 HP보다 큰 과잉 피해가 포함된다. 아래 실효 피해는 적 HP와 사건 순서를 재구성한 값이며 게임에서 자동 계측한 새 항목은 아니다. 제출 광역 두 번은 모두 3체가 살아 있고 각 HP가 60 이상일 때 적용돼 대상별 60·합계 180을 모두 유효하게 적용했다.

| 3회차 B→A 전환 | 과잉 피해가 많다고 느껴 HP 여유가 있을 때 피해를 분배하고 먼저 처치할 수 있는 적을 처리 | 의도적 타겟 변경. 과잉 피해 최소화나 최적 처치 순서가 실제로 달성됐다는 뜻은 아님 |
| 침묵 목적 | 주로 HP 보존과 짧은 시전으로 손패를 빠르게 순환시키기 위함 | 차단과 순환의 복합 목적. 0.2초 시전과 최소 0.4초 행동 잠금을 구분. 짧은 잠금은 일부 공격 카드와 공유하므로 침묵만의 독점 이점으로 보지 않음 |

**1차 해석:** 광역 효율·상대 기절 타이밍·다음 방어 준비·처치 대상 사이의 선택 의도가 확인됐다. 3회차 광역 보류를 카드 미인지로 단정하지 않는다. 이전의 “저코스트 공격으로 침묵의 순환 역할이 사라졌다”는 관찰을 모든 상황에 일반화하지 않는다. 이번에는 HP 보존과 순환을 함께 노렸다는 후속 근거가 있다.

**아직 결론 내리지 않는 것:** 광역이 단일보다 우수/열세, 긴 시전이 패배의 단독 원인, 정식 채택, 무정지 실시간 판단의 편의성, 반복 플레이의 재미. 특히 제출 두 광역 모두 정상 완료됐으므로 시전 취소 위험이 충분히 실측됐다고 하지 않는다.

- 요청: 사용자 추가 Maplestory 폰트, 일반 노랑·치명타 연한 빨강과 검정 테두리, 위로 이동하며 페이드. 사양 원본은 [10 A19](10_결정사항_로그.md#damage-numbers-20260922).

- 확인: 피해 숫자 16개·3전투 진행 42개·채널링 42개 검사 통과. Play 함수 호출 및 프레임 진행으로 정상 카드 피해·색·테두리·상승·페이드 확인. 검정 테두리 셰이더 키워드 누락을 화면 확인 중 수정하고 재검사. 마지막 Console 오류·경고 0건.

- 한계: 실제 마우스·키보드 조작·빌드는 미확인. 치명타 추첨·배율·플레이어 피격 숫자·타수별 분리 표시는 추가하지 않음. 기존 피해 계산·카드/적 데이터·덱·보상 규칙 유지. 연출 추가 뒤 계측은 UI 변경 전과 구분.
