### D-02 (2026-09-15)
- 한 일:
  - 프로젝트를 `Desktop/ScrollHunter` → `Documents/ScrollHunter`로 옮기고 GitHub 저장소에 연결. 그전까지 프로젝트가 저장소 밖에 있어 버전 관리가 전혀 안 되고 있었음
  - 1단계 완료 — CostSystem, SkillData(SO), DeckSystem(QWER·GCD), CombatUI
  - 2단계 완료 — EnemyData(SO), Enemy(캐스팅 루프), EnemyManager(0.5초 간격), Player(HP·피격·패배)
  - 한글 폰트(Gmarket Sans Medium) TMP 에셋화 → TMP 기본 폰트 + fallback 등록
  - 무대응 전멸 시각 **13.99초** 측정 (3단계 비교 기준)
- 막힌 것:
  - TMP 기본 폰트(LiberationSans)에 한글 글리프가 없어 카드 이름이 전부 두부(□)로 나옴. Dynamic 아틀라스 폰트 에셋을 만들어 해결
  - Unity 에디터가 포커스를 잃으면 플레이가 멈춰(`runInBackground` off) 플레이 검증이 안 됐음. 검증 중에만 켜고 되돌림
  - 1단계 테스트 덱을 임의값으로 채웠다가, `09` 문서에 밸런스시트 검증 덱 8장 표가 이미 있는 걸 뒤늦게 발견해 교체
- 판단한 것:
  - **덱 순환을 `SkillData[4]` + `Queue<T>`로 구현.** 쓴 카드를 Enqueue한 뒤 Dequeue해 같은 슬롯에 넣으면 슬롯 인덱스를 건드리지 않아 "카드가 왼쪽으로 밀리지 않는다"가 자동으로 성립한다. 덱 4장뿐인 경우에도 카드가 즉시 되돌아와 깨지지 않는다
  - **적 발동 간격은 EnemyManager가 중앙에서 강제.** 적이 각자 판단하면 동시 발동을 막을 수 없다. 캐스팅이 끝나도 허가가 날 때까지 대기하는 구조
  - **`Time.deltaTime` / `Time.time`만 사용.** 일시정지·배속이 별도 구현 없이 따라온다
  - 적 피해는 `피해량 × 감소율`로 계산. `공격력 × 계수`를 쓰지 않아 `EnemyData.attackPower`가 현재 미사용 상태 — **2026-09-15 해결: 공격력 스탯 자체를 폐지하고 피해량 절대값으로 통일 (`10` 문서 T13·N5)**
  - **적 행동 간격은 1.0초로 확정.** `04` §3.1 타임라인이 `발동 2.5s → 다음 캐스팅 4.5s`로 2.0초를 암시했으나, 스펙 표의 행동 간격 칸은 비어 있었고 명시적으로 값을 지정한 문서는 `09`의 "1초 휴식"뿐이었다. 타임라인 숫자를 오류로 보고 `3.5s`로 정정, §3.2·3.3에도 같은 기준으로 「다음 캐스팅 시작」 줄을 추가

### D-03 ( )
- 한 일:
  - **공격력 스탯 폐지.** `SkillData.coefficient(float)` → `damage(int)`로 교체하고 기존 값 × 100 적용
    (화염탄 100 / 서리화살 120 / 연쇄번개 50 / 폭발 110 / 관통 150 / 불기둥 90)
  - `EnemyData.attackPower` 필드 제거. 피해는 damage 필드만 사용
  - 피해 계산을 `Mathf.RoundToInt(damage × hitCount × 100f / (def + 100f) × crit)` 형태로 변경
  - 경계 처리 추가 — damage 0 → 0 / damage 1 + 방어 9999 → 1 / hitCount 0 → 1 보정
  - 검증: 30 → 25, 40 → 33, 150 → 125 전부 일치
  - **무대응 전멸 시각 재측정 13.99초 — 변동 없음**
  - 반올림 방식 재정정 — `Mathf.RoundToInt`도 은행가 반올림임을 실측으로 확인하고
    `Mathf.FloorToInt(raw + 0.5f)`로 교체
- 막힌 것:
  - [ ScriptableObject 필드명 변경 시 에셋 값 초기화 여부 등 ]
- 판단한 것:
  - **피해량 필드는 int, 계산 중간값만 float, 정수화는 최종 1회.** 카드에 찍히는 값이 소수면
    표시가 지저분하고 밸런싱만 어려워진다
  - **공식을 곱셈 먼저로 작성.** `damage × (1 - def/(def+100))` 형태는 나눗셈이 두 번 일어나
    30 → 24.999998이 되어 내림 시 24가 나온다. `damage × 100 / (def+100)`은 정확히 25
  - **반올림 구현을 실측으로 검증.** 문서 지시가 `Mathf.RoundToInt`였으나 직접 찍어보니
    `0.5→0, 2.5→2`로 은행가 반올림이었다. `Math.Round`를 피하려던 의도가 달성되지 않은 것.
    `Mathf.FloorToInt(raw + 0.5f)`로 교체해 올림 방향을 고정했다.
    **지시를 그대로 따르지 않고 실제 동작을 확인한 것이 문제를 조기에 잡았다**
  - B의 실피해가 33.3 → 33으로 바뀌었으나 누적 449.99 → 449로 사망 시점은 동일.
    **3단계 비교 기준 13.99초를 그대로 유지**
