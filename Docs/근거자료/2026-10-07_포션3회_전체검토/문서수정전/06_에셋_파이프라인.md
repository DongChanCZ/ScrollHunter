## 1. 이번 프로젝트에서 생성형 3D를 쓰는 이유

### 1.1 기대치 조정

> 생성형 3D는 아티스트를 대체하지 않습니다. 얻는 것은 "아트가 있는 팀 수준의 결과물"이 아니라 **"설계한 것을 그릴 수 있는 자유"**입니다.

| 해소되는 아쉬움 | 해소되지 않는 것 |
|---|---|
| 원하는 역할의 적을 만들 수 있음 | 스타일 통일 (회차마다 편차) |
| 실루엣으로 역할을 구분할 수 있음 | 리깅·애니메이션 |
| 팩에 없는 것을 포기하지 않아도 됨 | 토폴로지·폴리곤 품질 |
| | 모델당 1~2시간의 정리 비용 |

### 3.3 배경 제작 파일 (2026-10-07)

방향 원본 [10 A45](10_결정사항_로그.md#backgrounds-20261007). 보존 폴더는 [근거자료/2026-10-07_배경제작](근거자료/2026-10-07_배경제작/). Unity 반입·Battle 배치 완료. 적용·검사 [07](07_개발일지.md#d15-background-placement).

| 파일 | 용도 |
|---|---|
| BG01~BG04 PNG | 배경 컨셉 4종. BG01~03은 후면 2D 배경에 사용 |
| BG04_Cave_Backplate_Clean.png | 마법진을 뺀 동굴 후면 배경 |
| FX_BossWallCircle.png | 별도 보라 마법진. 검정 바탕이므로 Additive 재질 사용, 알파 PNG 아님 |
| P01~P07 FBX·GLB | 넓은 나무·높은 나무·관목·이끼 바위·동굴 입구·동굴 벽·석순 |
| P01~P07 BaseColor·Normal PNG | 모델에서 그대로 추출한 텍스처 |
| generation_manifest.json | 전체 프롬프트·워크플로 노드·원본 다운로드·배치 인계 |
| mesh_inspection.json·fbx_inspection.json | 메시·UV·텍스처·FBX 재반입 검사 |
| P01~P07 front·rear PNG | Blender 앞뒤 검수 화면 |

Unity 경로는 `Assets/_Project/Environment/`의 Models·Textures·Materials. FBX 7개·색/노멀 14장·배경/마법진 5장 반입. 모델 축 변환 유지, URP Lit 무광 재질·노멀 1K 사용. 나무는 중·원경, 적 주변은 비워둠. GLB·원본 이미지는 근거자료에 보존.

씬 `BattleEnvironment` 아래 4개 배경, `BattleEnvironment` 컴포넌트에서 전투별 전환·마법진 확대. 배치는 자식 Transform에서 조정. `Build Battle Backgrounds`는 없는 씬에 최초 생성할 때만 사용하며 기존 배경이 있으면 중단한다. FBX를 따로 재배치할 때 원본의 X=-90° 축 보정을 지우지 말 것.

2D 배경은 고정 카메라 후면, 화면비에 맞춰 빈틈 없이 확대. 이동 카메라용 지형은 아님. 기존 조명 유지·소품 그림자 끔·접지 그림자만 추가. 화면·기능 확인 완료, 직접 플레이·빌드 성능은 미확인.
