
### 2.2 P1 — 적을 관찰할 이유가 없음

블루아카이브의 코스트 + 손패 구조를 참조했으나, 두 지점에서 원본과 다르게 갔습니다.

| | 블루아카이브 | Soul Wanderer | 결과 |
|---|---|---|---|
| 카드 순환 | 무작위 추첨 | **결정론적 순환** (덱 맨 아래로) | 다음 카드를 완전히 예측 가능 |
| 쿨타임 | 없음 | 없음 | (동일) |
| 손패 교체 | 버리고 재추첨 가능 | **불가** | 나쁜 손패에 대처 불가 |
| 적 행동 대응 | 엄폐·지형 | **없음** | 적을 볼 이유 없음 |

무작위 추첨이 담당하던 긴장("원하는 카드가 오지 않을 수 있다")이 사라졌고, 대응 수단도 없어 **최적 로테이션이 계산 가능**해졌습니다. 그래서 플레이어는 캐스팅 바 3색을 읽을 필요가 없었습니다.

### 2.3 P2 — 맵 선택에 의미가 없음 (이번 범위 밖, 분석만)

| 항목 | 1차 설계 | 문제 |
|---|---|---|
| 타일 정보 | 미탐색 구역으로 가림 | 선택이 판단이 아닌 도박이 됨 |
| 방문 제한 | 명시 없음 | 전부 방문 가능하면 선택이 아니라 체크리스트 |
| HP 인계 | 명시 없음 | HP가 자원인지 아닌지 불명확 → 전투 회피 동기 미성립 |
| 그냥 길 타일(2) | 아무 일 없음 | 존재 이유 미정의 |

> 잘한 점: 절차적 생성 알고리즘을 6단계 도해로 명시했고, 제약 조건(엘리트 비인접, 보스 최원거리, 연속 배치 금지)을 정의했으며, 생성 예시 10장으로 결과를 검증했습니다. **기술적 설계는 충실했으나 플레이어 의사결정 설계가 비어 있었습니다.**
>
> 참고로 문서에 "탐색 구역 없이 바로 타일 종류를 보여주는 것으로 디자인할 수도 있음"이라는 대안이 기록되어 있었는데, 그 대안이 오히려 정답에 가까웠습니다.

## 4. 재설계 방향

### 4.1 핵심 명제

> 결정론적 순환을 무작위로 되돌리지 않는다. 대신 **적의 캐스팅에 대응 수단을 부여**하여 최적 로테이션을 깨뜨린다.

### 4.2 개선 항목

| 문제 | 개선 | 기대 효과 | 검증 방법 |
|---|---|---|---|
| P1 | 캐스팅 3색에 각각 대응 수단 부여 (초록=무시 / 주황=차단 / 빨강=방어도) | 적을 관찰할 이유가 생김 | 18일차 실측: 전투당 차단·방어 카드 사용 횟수 |
| P1 | 대기열 다음 1장을 미리 표시 | 결정론을 숨기지 않고 플래닝 도구로 전환 | 테스터가 "카드를 끌어오기 위해" 코스트를 쓰는지 관찰 |
| P1 | 일시정지 재설계 [ 정지 중 카드 사용 불가 / 횟수 제한 / 제거 ] | 계산 시간 무한 제공 방지 | [ ] |
| P0 | 모든 문서에 변경 이력 표 + 개발 일지 | 문서와 빌드의 동기화 | 제출 시 변경 이력 3건 이상 |
| P3 | 스코프를 §5 범위로 고정, 11일차 기능 동결 | 후반부 미완성 방지 | 11일차 이후 신규 기능 0건 |

### 4.3 새 핵심 루프

```
적 3체의 캐스팅 바를 읽는다 (색 + 남은 시간)
  ↓
어느 것이 위협적인가 판단
  ↓
필요한 카드가 손패에 있는가? 없다면 대기열 몇 번째인가?
  ↓
한정된 코스트를 어디에 쓸 것인가 결정
  ├ 딜을 넣는다 (로테이션 유지)
  ├ 차단·방어 카드를 쓴다 (로테이션 포기)
  └ 카드를 끌어오기 위해 다른 카드를 소모한다 (코스트 낭비)
  ↓
막지 못한 것은 감수한다
```

> **"쓸 수 있는데 안 쓰고 참는" 순간과 "쓸 게 없어서 억지로 쓰는" 순간**을 동시에 만드는 것이 목표입니다.

### 4.4 구현 환경 변경

| 항목 | 1차 | 2차 | 변경 이유 |
|---|---|---|---|
| 차원 | 2D | 3D | [ 보스 스케일에 의한 압박감 / 스킬 컷인 카메라 연출 등 — 1~2개만 적을 것 ] |
| 에셋 | 구매·무료 2D 에셋 팩 (팀에 아트 인원 없음) | 생성형 AI (VARCO 3D) + 무료 에셋 | [아래 4.5] |
| 개발 인원 | 팀 O명 | 1인 (기획 + 구현) | 수업 조건 |

> 3D는 목표가 아니라 재설계의 실현 수단입니다. **"3D로 바꿔서 실제로 얻는 것"을 1~2개만 적고, 그것만 하세요.**
> 캐스팅 바 텔레그래프가 UI에 있으므로 생성형 3D 모델에 공격 모션이 없어도 시스템이 성립합니다. (설계상 이점)

### 4.5 아트 제약이 설계에 미친 영향 ★

<!-- 이번 프로젝트의 개인적 동기이자, 실은 설계 문제이기도 합니다. -->

1차 프로젝트는 팀에 아트 인원이 없어 기존 에셋 팩만으로 제작했습니다. 그 결과 **설계가 에셋을 따라갔습니다.**

| 근거 | 내용 |
|---|---|
| 맵 문서 몬스터 표 | 각 적이 `이미지 코드 138 / 166 / 147 / 111 / 142`로 관리됨 — 에셋 팩의 번호 |
| 순서 | "이런 역할의 적이 필요하다 → 만든다"가 아니라 "쓸 수 있는 그림이 이것들이다 → 여기서 고른다" |
| 결과 | 적 5종의 역할이 분화되지 않음. 타겟 선택에 의미가 생기지 않음 (P1과 연결) |

**이번 변경:**

| | 1차 | 2차 |
|---|---|---|
| 설계 순서 | 보유 에셋 → 적 설계 | **적 설계 → 에셋 생성** |
| 적의 정체성 | 그림에서 역산 | **담당 색상(🟢🟠🔴)에서 출발** |
| 제약 | 팩에 존재하는 것만 | 설계한 것을 만들 수 있음 |

`04_적_패턴_기획서`의 색상 담당 설계(주황 전담 적 = 차단 대상, 빨강 전담 적 = 방어 대상)를 **외형으로도 구현**할 수 있게 됩니다. 차단해야 하는 적은 주문을 외는 실루엣으로, 방어해야 하는 적은 크고 둔중한 실루엣으로. 1차 때는 에셋 팩에 없으면 포기해야 했던 부분입니다.

> **주의 — 이번 프로젝트에서 지킬 것**
> - 아트 품질은 평가 목표가 아닙니다. 여전히 **12일차 이후**에 에셋을 붙이고, 그 전까지는 회색 캡슐로 전투를 완성합니다
> - 생성형 3D는 아티스트를 대체하지 않습니다. 스타일 편차, 리깅 불가, 모델당 1~2시간의 정리 비용이 있습니다
> - 얻는 것은 "아트가 있는 팀 수준의 결과물"이 아니라 **"설계한 것을 그릴 수 있는 자유"**입니다
