## 1. 설계 목표

> 런이 끝날 때마다 다음 런이 조금씩 달라지게 한다.
> 강해지는 것 자체보다, **다음 런의 덱 구성이 달라지는 것**이 핵심이다.

| 원칙 | 내용 |
|---|---|
| 획득은 1개 | 런당 1개만 계승. 선택의 무게를 유지 |
| 성장 축은 둘 | 카드(덱 구성 변화) / 패시브(스탯 강화) |
| 난이도는 자동으로 오르지 않음 | 플레이어가 등급을 선택 (§6) |
| 실패도 보상 | 패배해도 계승. 진행이 헛되지 않음 |

## 2. 계승 흐름

```
런 종료 (승리 또는 패배)
  ↓
[결과 화면]
  도달 전투 / 처치 수 / 총 피해 / 사용 카드 통계
  ↓
[계승 선택]
  이번 런에서 획득한 카드·패시브를 전부 나열 → 1개 선택
  ↓
  ├─ 패시브 선택 → 즉시 계승 목록에 추가 (끝)
  └─ 카드 선택 → 시작 덱의 어느 슬롯을 대체할지 선택
  ↓
[시작 화면]
  계승 목록 표시 / 난이도 등급 선택 / [초기화] 버튼
  ↓
다음 런 시작
```

### 2.1 계승 선택 화면

```
┌────────────────────────────────────────────┐
│  계승 — 하나를 다음 런으로 가져갑니다          │
│                                             │
│  이번 런에서 획득한 것                        │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐     │
│  │🃏 성역│ │🃏 속박│ │✨포션+1│ │✨코스트│     │
│  │방어180│ │차단2초│ │       │ │+0.1   │     │
│  └──────┘ └──────┘ └──────┘ └──────┘     │
│                                             │
│  🃏 카드는 시작 덱의 슬롯 1칸을 대체합니다     │
│  ✨ 패시브는 그대로 누적됩니다                │
│                        [ 선택 ]              │
└────────────────────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 나열 대상 | 그 런에서 **보상으로 획득한 것만** (시작 덱 카드는 제외) |
| 선택 개수 | 1개 |
| 스킵 가능 | [ 가능 / 불가 ] — **불가 권장.** 선택하지 않을 이유가 없음 |
| 아무것도 못 얻은 런 | 전투 1에서 패배 시 획득물 0개 → 계승 없이 넘어감 |

## 3. 카드 계승 — 슬롯 덮어쓰기

<!-- 덱은 8장 고정입니다. 계승이 무제한이면 규칙이 무너지므로, 슬롯을 덮어쓰는 방식으로 자연 상한을 만듭니다. -->

### 3.1 규칙

| 항목 | 규칙 |
|---|---|
| 방식 | 계승 카드가 **시작 덱의 특정 슬롯(1~8)을 영구 대체** |
| 선택 시점 | 계승할 때 어느 슬롯을 대체할지 지정 |
| 이미 계승 카드가 있는 슬롯 | 선택 가능. 기존 계승 카드는 **소멸** |
| 자연 상한 | **8장** (덱 크기와 동일). 별도 규칙 불필요 |
| 순서 변경 | 런 시작 시 덱 편성 화면에서 자유롭게 |

### 3.2 슬롯 선택 화면

```
┌────────────────────────────────────────────┐
│  「성역」을 어느 슬롯에 넣을까요?              │
│                                             │
│  ── 시작 손패 ──      ── 대기열 ──          │
│  [1]화염탄  [2]서리화살  [5]연쇄번개 [6]폭발  │
│  [3]수정방패 [4]침묵     [7]관통   [8]불기둥  │
│    ✨계승                                    │
│                                             │
│  ※ 3번은 이미 계승 카드입니다. 선택 시 교체됩니다 │
└────────────────────────────────────────────┘
```

**시작 손패(1~4)와 대기열(5~8)을 시각적으로 구분**하세요. 앞 슬롯에 넣으면 전투 시작부터 손에 들어오고, 킵 플레이가 가능합니다. 이 구분이 보여야 슬롯 선택이 의미 있는 결정이 됩니다.

### 3.3 왜 이 방식인가

| 대안 | 문제 |
|---|---|
| 별도 계승 카드 목록에서 매 런 선택 | UI가 하나 더 생기고, 런 시작 흐름이 길어짐 |
| 계승 카드를 덱에 추가 (9장, 10장…) | 덱 8장 고정이 깨지고 1사이클 계산이 무너짐 |
| **슬롯 덮어쓰기 (채택)** | 자연 상한 8장, UI 한 화면, 시작 덱이 점진적으로 나만의 것이 됨 |

## 4. 패시브 계승

| 항목 | 규칙 |
|---|---|
| 방식 | 계승 목록에 추가, 다음 런부터 자동 적용 |
| 누적 | 무제한 (단 항목별 상한 존재) |
| 중복 | 같은 패시브를 여러 번 계승 가능 (스택) |
| 상한 도달 시 | **보상 추첨 풀에서 자동 제외** → 애초에 선택지에 안 나옴 |

### 4.1 항목별 상한

| 패시브 | 증가폭 | 상한 | 근거 |
|---|---|---|---|
| 코스트 회복 속도 | +0.1 | **1.2 (4스택)** | 회복량 기준 계산과 상한 밖 가정 비교는 03 §7.3 참조. 실전 영향은 별도 시험 |
| 포션 횟수 | +1 | [ 6 ] | [ ] |
| 최대 HP | +50 | [ 상한 없음 ] | [ ] |
| 방어도 부여량 | +20% | [ +100% ] | [ ] |
| 차단 경직 시간 | +0.5초 | [ +2초 ] | [ ] |
| [ ] | [ ] | [ ] | [ ] |

> **코스트 회복만 반드시 상한이 필요합니다.** 밸런스 시트의 모든 계산이 이 값 위에 서 있습니다.

### 4.2 상한 표시

| 위치 | 표현 |
|---|---|
| 보상 화면 | 상한 도달 시 **추첨 풀에서 제외.** 회색 처리보다 아예 안 보이는 쪽이 깔끔함 |
| 계승 목록 | `코스트 회복 +0.1 (3/4)` / 상한 도달 시 `(4/4 MAX)` |
| 전투 화면 | 코스트 게이지 옆에 현재 회복 속도 `0.8/s` |

## 5. 시작 화면

```
┌────────────────────────────────────────────┐
│           SCROLL HUNTER                     │
│                                             │
│  난이도 등급   [ 0 ] ◀ ▶   (해금: 2)        │
│                                             │
│  계승 목록                                   │
│  🃏 성역 (슬롯 3)   ✨ 포션 +1               │
│  🃏 속박 (슬롯 4)   ✨ 코스트 회복 +0.1 (2/4) │
│                                             │
│       [ 런 시작 ]    [ 계승 초기화 ]          │
└────────────────────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 계승 목록 | 카드는 슬롯 번호와 함께, 패시브는 스택 수와 함께 |
| 초기화 | **확인 팝업 필수.** "모든 계승이 사라집니다. 난이도 해금은 유지됩니다" |
| 초기화 범위 | 계승만 삭제. **난이도 해금 기록은 유지** |

| 7 | 195% | 등급 6 클리어 |

| 항목 | 규칙 | 근거 |
|---|---|---|
| 배율 계산 | 이전 등급 × 1.1 (복리) | [ ] |
| 상한 | 등급 7 | 무한이면 언젠가 클리어 불가능 |
| 적용 대상 | 적 **체력과 피해량만** | 캐스팅 시간까지 줄이면 대응 자체가 불가능해짐 |

## 7. 저장 데이터 (JSON)

### 7.1 구조

```json
{
  "version": 1,
  "inheritedCards": [
    { "slot": 3, "skillId": "SK12" },
    { "slot": 4, "skillId": "SK09" }
  ],
  "inheritedPassives": [
    { "passiveId": "POTION_PLUS", "stack": 1 },
    { "passiveId": "COST_REGEN", "stack": 2 }
  ],
  "maxUnlockedDifficulty": 2,
  "stats": {
    "totalRuns": 7,
    "clears": 2,
    "bestDifficulty": 2
  }
}
```

### 7.2 규칙

| 항목 | 값 |
|---|---|
| 저장 위치 | `Application.persistentDataPath` |
| 파일명 | `save.json` |
| 저장 시점 | 계승 선택 완료 시 / 난이도 해금 시 |
| **저장하지 않는 것** | **런 진행 상황** (중간 저장 없음) |
| `version` 필드 | 구조 변경 시 마이그레이션용. **처음부터 넣어둘 것** |
| 파일 손상 시 | 초기 상태로 복구, 사용자에게 알림 |

> **`version` 필드를 지금 넣어두세요.** 출시 후 저장 구조를 바꿀 때 이게 없으면 기존 플레이어의 데이터가 전부 깨집니다. 나중에 추가할 수 없는 항목입니다.

## 8. 구현 순서

| 시점 | 작업 |
|---|---|
| 프로토타입 1~4단계 | **구현하지 않음.** 전투 재미 검증이 우선 |
| 9~11일차 | 보상 3택1 + 덱 리빌딩 |
| 미정 (기존안: 16~17일차) | 계승 시스템. 07의 11일차 기능 동결과 충돌하므로 일정 재결정 전 착수하지 않음 |
| 여유 시 | 난이도 등급 |

> 1단계 `DeckSystem`을 만들 때 **"덱 구성은 외부에서 주입받는다"** 구조로만 짜두면, 나중에 계승 카드를 끼워 넣기 쉽습니다.

## 9. 검증

| 항목 | 방법 | 목표 |
|---|---|---|
| 계승이 다음 런을 바꾸는가 | 2런 연속 플레이 | 덱 구성이 달라짐 |
| 슬롯 선택이 고민되는가 | 테스터 관찰 | 3초 이상 망설임 |
| 코스트 회복 상한이 작동하는가 | 4스택 후 보상 확인 | 추첨 풀에서 제외됨 |
| 저장이 유지되는가 | 게임 재시작 | 계승 목록 그대로 |
| 초기화가 작동하는가 | 초기화 후 재시작 | 계승만 삭제, 난이도 해금 유지 |
