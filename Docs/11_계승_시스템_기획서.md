# 11. 계승 시스템 기획서

**프로젝트** Scroll Hunter | **작성자** [ ] | **문서 버전** v1.2

> 패배 후 계승·JSON 저장 구현. 확정 규칙은 [10 C](10_결정사항_로그.md#inheritance-20261008), 작업·검사는 [07 D-16](07_개발일지.md#d16-inheritance), 직접 확인은 [09](09_프로토타입_제작절차.md#inheritance-checks) 참조. 승리 후 신규 계승·난이도 선택은 후속안.

## 1. 설계 목표

실패한 런에서 얻은 선택지를 다음 도전에 남긴다. 스킬은 시작 편성을 바꾸고, 패시브는 능력치를 누적한다. 효과·상한은 03 PS와 10 B14를 따른다.

## 2. 화면 흐름

패배 연출 → 결과 → 계승 선택 → 다음 런 편성 → 전투 시작. 스킵·후보 없음도 바로 편성. 순서 변경은 기존 드래그·저장/취소 사용.

- 기존 보상 화면에서 계승 후보를 고른다. 스킬은 시작 덱의 교체 자리 선택 → 「확인」으로 저장. 버튼·선택 표시는 [10 후속](10_결정사항_로그.md#replacement-confirmation-20261008).
- 시작 화면 「계승 정보」에서 시작 덱·계승 자리·패시브 스택을 확인한다. 두 목록을 나누고 이름과 보조 정보의 크기를 구분한다. 표시 기준은 [10 A47](10_결정사항_로그.md#main-menu-20261008).
- 「계승 초기화」는 계승만 삭제. 옵션의 「게임 초기화」는 튜토리얼·클리어 기록도 함께 삭제. 화면·소리 설정은 유지. 둘 다 확인 창을 거친다. [10 A47 후속](10_결정사항_로그.md#menu-progress-20261008). 스킵·후보 제외·튜토리얼 예외·저장 오류 규칙은 10 C에 둔다.
- 현재 본편은 보상 기회 3회이므로 기존 후보 3칸을 사용한다. 보상 횟수를 늘리면 후보 화면도 함께 검토한다.

## 4. 구현·확인

- `BattleFlow`: 획득 기록·계승 선택·다음 런 적용.
- `InheritanceSave`: 저장·불러오기·초기화. 실제 형식·위치는 10 C 참조.
- `BattleRewardUI`: 기존 후보/덱 화면 재사용, 시작 화면의 계승 정보·초기화 연결.
- 기능 확인과 체감은 구분한다. 직접 2런을 이어서 플레이하고 선택 이유·다음 런의 변화를 기록한다. 계승이 무조건 좋은 밸런스라는 판정은 하지 않는다.
- 실측할 때 계승 목록도 조건에 기록한다. 계승 없는 과거 런과 섞지 않는다.
