## 1\. 설계 목표

> 플레이어가 자기 손패뿐 아니라 적의 캐스팅을 보게 만든다. 최적 로테이션이 존재하되, 적의 행동이 그것을 계속 깨뜨리게 한다. 결정론적 순환을 숨기지 않고 플래닝 도구로 전환한다.

### 1.1 장르 좌표

| 축 | 선택 | 근거 |
| :---- | :---- | :---- |
| 시간 진행 | 실시간 (일시정지 가능) | \[ 일부 툴팁을 읽거나 정지하고 순간 판단을 생각할 시간을 줌 \] |

| 결정에 주어지는 시간 | 적 캐스팅 시간 내 | \[ 상대방의 기술에 대한 대처를 하는 플레이 경험 \] |

### 4.1 행동 잠금 (GCD) ★

행동 잠금 시간 \= MAX(카드 캐스팅 시간, 최소 GCD)

| 항목 | 값 | 근거 |
| :---- | :---- | :---- |
| 최소 GCD | \[ 0.4 \]초 | 0.3초 이하는 없는 것과 같고, 1.0초 이상이면 실시간인데 턴제처럼 느껴짐 |
| 즉발기 캐스팅 | \[ 0.2\~0.4 \]초 | 최소 GCD에 흡수됨 |
| 캐스팅기 캐스팅 | \[ 0.8\~1.5 \]초 | 그 시간 전체가 잠금 |
| 차단·방어 카드 캐스팅 | \[ 0.2\~0.3 \]초 | **반드시 짧아야 함.** 길면 대응 자체가 불가능해짐 |
| 포션(Shift) | 잠금 \[ 미적용 \] | 긴급 회복이 막히면 조작이 답답해짐 |
| UI | 슬롯 위에 남은 시간 표시 (1차 계승) | \[ \] |

> **발동 방식 추가(2026-09-21):** 일반 시전과 채널링은 효과 시점이 다르다. 공통 정의·종료 처리는 [10 A18](10_결정사항_로그.md#channeling-definition), 제작·확인은 [09](09_프로토타입_제작절차.md#channeling-authoring) 참조. 아래 무방비 예시는 일반 시전 기준이다.

### 4.2 캐스팅 시간이 기회비용이 되는 구조

> 캐스팅 중에는 다른 카드를 쓸 수 없으므로, **캐스팅 시간 \= 적에게 대응할 수 없는 시간**입니다.

발생하는 판단:

> 불기둥(캐스팅 1.2초)을 쓰기 시작했다. 0.3초 뒤 적 B의 주황 캐스팅이 시작됐다. 캐스팅이 끝나기 전까지 침묵을 쓸 수 없다.

즉 카드를 쓰기 **전에** "지금 이 1.2초 동안 적이 무엇을 시작할 것 같은가"를 계산해야 합니다. 적의 캐스팅 바를 봐야 할 이유가 하나 더 생깁니다.

| 카드 유형 | 캐스팅 | 성격 |
| :---- | :---- | :---- |
| 즉발 고코스트 | 0.3초 | 비싸지만 언제든 낼 수 있음. 안전 |
| 캐스팅 고위력 | 1.2초 | 싸고 강하지만 그 시간 동안 무방비 |
| 차단·방어 | 0.2\~0.3초 | 반드시 짧게 |

### 4.3 두 개의 병목

카드 접근 시간은 입력 순서에 따른 코스트 충전과 행동 잠금을 함께 계산합니다. **손패 진입·사용 가능·효과 적용 시점은 서로 다릅니다.**

| 제약 | 언제 병목이 되는가 |
| :---- | :---- |
| 코스트 | 코스트가 비어 있을 때 |
| 행동 잠금 | 코스트를 모아뒀을 때 |

> 예: 차단 카드가 덱 6번 슬롯 → 앞 2장을 써야 손에 옴  
> 

> - 코스트 0에서 시작 → 코스트 7 필요 → 0.8/초면 **8.75초**  
> - 코스트 10, 앞 두 카드가 화염탄·서리화살이면 → 0초·0.4초에 입력 → 6번 카드는 **0.4초에 손패 진입**, 잠금은 **0.8초에 종료**. 그 카드의 사용 코스트는 별도 확보

>   
> **코스트를 미리 모으면 카드 접근이 빨라집니다.** 엑셀 `덱시뮬`은 지정 순서의 비용·잠금 합을 비교하는 참고 계산이며, 실제 입력 시각이나 사용 후 재등장을 시뮬레이션하지 않습니다.

### 4.4 균형 검증 (엑셀 `덱시뮬` 시트 연동)

## 6.5 타겟팅 ★

### 6.5.1 분류별 대상 규칙

| 분류 | 대상 | 지정 방식 |
| :---- | :---- | :---- |
| 딜 / 단일 | **타겟 1체** | 마우스 클릭 또는 좌우 방향키 |
| 딜 / 광역 | **적 전체** | 지정 불필요 |
| 차단 | **타겟 1체** (캐스팅 중일 때만 사용 가능) | 위와 동일 |
| 방어 | **자신** | 지정 불필요 |

> **분류를 보면 대상이 정해집니다.** 차단 전용 타겟이나 별도 순환 키를 두지 않습니다. 조작이 하나 늘어날 때마다 학습 부담이 커지고, 실시간 게임에서는 그 부담이 판단 시간을 잡아먹습니다.

| 항목 | 규칙 | 근거 |
| :---- | :---- | :---- |
| 조작 | 마우스 클릭 / 좌우 방향키 | SW 계승. 왼손 QWER \+ 오른손 방향키로 손을 떼지 않고 플레이 가능 |
| 마커 | 대상 위 조준 마커, 맥동 효과 | SW 계승 |
| 초기 타겟 | 전투 시작 시 **1번 적 자동 지정** | \[ \] |
| 타겟 사망 시 | **자동으로 다음 생존 적**으로 이동 | 수동 재지정은 판단이 아니라 귀찮음 |
| 방향키 순서 | 화면 배치 좌→우, 죽은 적은 건너뜀 | \[ \] |
| 광역기 사용 시 | 타겟 무시, 마커는 유지 | \[ \] |

### 6.5.3 딜과 차단이 타겟을 공유하는 결과

> 적 A에게 딜을 집중하던 중 적 B가 주황 캐스팅을 시작했다. 차단하려면 타겟을 B로 옮겨야 하고, **그러면 다음 단일 딜기도 B에게 나간다.**

거의 죽어가던 A를 놔두고 B로 가야 합니다. 의도한 게 아니라 타겟을 하나로 둔 결과 자동으로 따라오는 긴장입니다.

그리고 여기서 **광역기의 성격이 또렷해집니다.** 광역은 타겟과 무관하므로, 타겟을 B로 옮긴 상태에서도 A와 B를 함께 칩니다. **타겟을 옮겨야 하는 상황에서 딜 손실을 줄이는 카드**가 됩니다.

### 6.5.4 손패 슬롯 비활성화 처리 ★

차단 카드는 **타겟이 캐스팅 중이 아니면 슬롯이 비활성**입니다. 아예 누를 수 없으므로 잘못 쓰는 사고가 구조적으로 사라집니다.

비활성 사유가 **넷**이므로 **시각적으로 구분**해야 합니다. 전부 똑같이 회색이면 플레이어가 원인을 모릅니다.

| 사유 | 적용 범위 | 표시 |
| :---- | :---- | :---- |
| 코스트 부족 | 해당 슬롯만 | 어둡게 \+ 코스트 숫자를 빨갛게 |
| **타겟이 캐스팅 중이 아님** | **차단 카드만** | 어둡게 \+ 자물쇠 아이콘 (또는 테두리 점선) |
| 행동 잠금 중 | 손패 전체 | 어둡게(회색) \+ 남은 시간 숫자 |
| **기절 중** | **손패 전체** | 어둡게(**보라 계열**) \+ 남은 시간 숫자 \+ **화면 중앙에 기절 표시** |

> **타겟을 옮기면 즉시 밝아집니다.** 그 변화 자체가 "캐스팅 중인 적을 타겟으로 잡아야 한다"를 가르칩니다. 튜토리얼 텍스트 없이 규칙이 전달되는 지점입니다.

#### 행동 잠금과 기절을 반드시 구분할 것 ★

둘 다 「손패 전체 \+ 남은 시간 숫자」라 그대로 두면 화면이 똑같습니다. 플레이어에게는 0.4초짜리 GCD와 2초짜리 행동 불능이 완전히 다른 사건이므로 **두 가지를 함께** 적용합니다.

| 수단 | 내용 |
| :---- | :---- |
| **슬롯 색** | 행동 잠금 \= 회색 / 기절 \= 보라 계열. 눈으로 즉시 갈린다 |
| **화면 중앙 표시** | 기절일 때만 중앙에 `기절 2.0` 표시. 2초 행동 불능은 슬롯 구석 숫자보다 크게 알려야 하는 사건이다 |

> 색만 쓰면 손패를 안 보고 있을 때 놓치고, 중앙 표시만 쓰면 "어느 카드가 왜 죽었는지"가 안 보입니다. 슬롯 색은 **원인**을, 중앙 표시는 **상태**를 알립니다. 역할이 달라 둘 다 필요합니다.

| 상황 | 처리 | 근거 |
| :---- | :---- | :---- |
| 타겟이 캐스팅 중 아님 | **비활성** (사용 불가) | UI로 막는 것이 규칙으로 막는 것보다 낫다 |
| 타겟이 🟢 초록 또는 🟠 주황 캐스팅 중 | 활성. 효과 적용 시에도 해당 캐스팅 중이면 성공 | 시전 0.2초 사이에 발동하면 실패·경직 없음 |
| 타겟이 🔴 빨강 캐스팅 중 | **활성, 실패** (코스트 소모) | 비활성으로 막으면 "빨강은 차단 불가"를 배울 기회가 사라짐 |

## 7\. 데미지 공식

> **플레이어에게 공격력 스탯은 없습니다.** 피해는 스킬 카드에 적힌 피해량(절대값)으로만 결정됩니다.

최종피해 \= (스킬 피해량 × 타수) × 100 / (대상 방어력 \+ 100\) × 크리티컬배율

     ※ 실제 구현은 §7.3의 형태를 따를 것

방어감소율 \= 대상 방어력 / (대상 방어력 \+ 100\)

크리티컬배율 \= 크리티컬 발생 시 1.8, 아니면 1.0

피해 적용 \= 방어도에서 먼저 차감 → 남은 피해를 HP에서 차감

### 7.1 각 항의 존재 이유

| 항 | 왜 이렇게 설계했는가 |
| :---- | :---- |
| **공격력 스탯을 두지 않음** | 카드에 적힌 숫자가 곧 피해량이라 플레이어가 직접 읽고 계산할 수 있다. "계수 1.2"는 공격력을 알아야 의미가 생기지만 "피해 120"은 그 자체로 정보다. 밸런싱도 카드 하나만 고치면 된다. 1차 버전(SW)도 "40 데미지 2회타격" 형태의 절대값이었다 |
| 비율 감소가 다단히트에 유리 | 감산 방식이면 타수가 많을수록 손해지만(매 타격마다 차감), 비율 방식은 총량 기준이라 다단히트가 불리하지 않다. 불기둥(90×2) 같은 카드가 정상 작동하는 근거 |
| 방어력을 비율 감소로 | 감산 방식은 방어력이 피해량을 넘는 순간 피해가 0이 되어 밸런스 구간이 좁다. 나눗셈 방식은 방어력이 높아져도 수익이 체감할 뿐 0이 되지 않아, 20일 규모에서 수치 조정 실패 위험이 낮다고 판단 |
| 크리티컬 배율 1.8 | \[ \] |
| 상수 100 | \[ \] |
| 방어도를 별도 레이어로 | \[ \] |

### 7.2 딜 성장은 카드 교체로만

공격력 스탯이 없으므로 **"공격력 \+10" 같은 패시브는 만들 수 없습니다.** 딜 성장은 오직 더 좋은 카드로 덱을 교체하는 것으로 이뤄집니다. 덱 빌딩 중심 설계에 부합합니다.

딜 강화 패시브가 필요하다면 형태가 달라집니다.

| 불가 | 가능 |
| :---- | :---- |
| 공격력 \+10 | 모든 스킬 피해 **\+10%** |
|  | 크리티컬률 \+5% |
|  | 크리티컬 배율 \+0.2 |

> **퍼센트 방식은 무제한 누적 시 위험합니다.** 계승 10스택이면 피해가 2배가 됩니다. 도입 시 반드시 상한을 두세요. 현 설계에서는 도입하지 않습니다.

### 7.3 수치 타입과 반올림 ★

| 층 | 타입 | 이유 |
| :---- | :---- | :---- |
| SkillData.damage, EnemyData.damage (저장·표시) | **int** | 카드에 찍히는 값. 소수 피해량은 표시가 지저분하고 밸런싱만 어려워짐 |
| 계산 중간값 | **float** | 방어 감소·크리티컬이 곱해지는 구간 |
| 최종 적용값 | **int** | HP·방어도가 int이므로 여기서 **한 번만** 정수화 |

> **정수화는 마지막 한 곳에서만 합니다.** 중간에 여러 번 자르면 오차가 누적됩니다.

#### 공식을 쓰는 형태

// ❌ 뺄셈 먼저 — 부동소수점 오차

30f \* (1f \- 20f/120f)  \= 24.999998f   → 내림 시 24

// ✅ 곱셈 먼저 — 나눗셈 1회

30f \* 100f / (20f \+ 100f) \= 25.0f     → 25

같은 식이지만 **곱셈을 먼저 하면 나눗셈이 한 번만 일어나 오차가 줄고**, 문서에 적힌 실피해값과 정확히 일치합니다.

float raw \= damage \* hitCount \* 100f / (targetDefense \+ 100f) \* critMultiplier;

if (raw \<= 0f) return 0;                          // 피해량 0인 카드는 0 유지

return Mathf.Max(1, Mathf.FloorToInt(raw \+ 0.5f)); // 올림 방향 고정 \+ 최소 1

> **`Mathf.RoundToInt`를 쓰지 마세요.** 이름과 달리 은행가 반올림(round half to even)입니다. `0.5 → 0`, `1.5 → 2`, `2.5 → 2`, `3.5 → 4` 로 .5에서 짝수에 붙습니다. `Math.Round` 기본값도 동일합니다. `FloorToInt(x + 0.5f)`는 항상 올림 방향으로 고정되어 설계자가 예상한 값과 일치합니다.

| 항목 | 규칙 | 근거 |
| :---- | :---- | :---- |
| 소수점 처리 | **반올림 (올림 방향 고정)** | 내림이면 오차로 25가 24가 되는 사고를 못 막음 |
| 반올림 구현 | **`Mathf.FloorToInt(raw + 0.5f)`** | ⚠️ `Mathf.RoundToInt`와 `Math.Round`는 **둘 다 은행가 반올림**이라 .5에서 짝수로 붙는다 (0.5→0, 2.5→2). 사용 금지 |
| 최소 피해 | **1** (단 피해량 0인 카드는 0 유지) | 방어력이 아무리 높아도 1은 들어가되, 차단·방어 카드가 피해를 주면 안 됨 |
| 도트 피해 틱 | \[ 1초마다 / 총 O회 \] | \[ \] |

#### 검증값 (프로토타입 2단계 기준, 플레이어 방어력 20\)

| 적 | 피해량 | 계산 | 최종 |
| :---- | :---- | :---- | :---- |
| A | 30 | 30 × 100 / 120 | **25** |
| B | 40 | 40 × 100 / 120 | **33** |
| C | 150 | 150 × 100 / 120 | **125** |

#### 반올림 동작 검증

| 입력 | `Mathf.RoundToInt` (금지) | `FloorToInt(x+0.5f)` (채택) |
| :---- | :---- | :---- |
| 0.5 | 0 ❌ | **1** |
| 1.5 | 2 | **2** |
| 2.5 | 2 ❌ | **3** |
| 3.5 | 4 | **4** |
| 12.5 | 12 ❌ | **13** |

#### 교체 시점의 밸런스 영향 (2026-09-15 확인)

값이 실제로 달라지는 조건은 **raw가 정확히 `.5`이고 정수부가 짝수**일 때뿐입니다. 방어력 20(`×5/6`) 기준으로는 `피해량 × 타수`가 **3, 15, 27, 39…** (12 간격)인 경우입니다.

| 방향 | 현재 상태 | 영향 |
| :---- | :---- | :---- |
| 플레이어 → 적 | **적 방어력 0** → `raw = 피해량` (소수부 없음) | 없음 |
| 적 → 플레이어 | 방어력 20\. 피해량 30·40·150 | 해당 조합 없음 |

> **밸런스 변화 0으로 안전하게 교체 가능한 시점이었습니다.**  
>   
> ⚠️ **3단계에서 재확인할 것.** 적에게 방어력이 생기면(`10` 문서 N4) 플레이어 → 적 방향에도 소수가 생기고, 크리티컬 1.8배까지 곱해져 조합이 늘어납니다. 적 방어력을 확정할 때 카드 8장의 raw를 한 번 찍어보고, **밸런스시트의 기대값과 실제 구현값이 일치하는지** 확인하세요. 시트는 소수를 그대로 들고 있고 게임은 정수로 떨어뜨립니다.
