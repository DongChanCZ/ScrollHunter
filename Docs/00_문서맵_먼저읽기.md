## 1차 버전 분석 결과 (회고의 출발점)

두 기획서(전투 / 맵과 스테이지, 모두 Version02)를 분석해 나온 문제입니다. 01 문서에 그대로 반영되어 있으니, **본인이 실제로 관찰한 내용으로 근거 칸을 채우세요.**

| # | 문제 | 이번 범위 |
|---|---|---|
| P0 | 문서와 구현의 불일치 (두 문서 공통) | ✅ 절차로 해결 |
| P1 | 캐스팅 바 3색에 대응 수단이 없음 → 로테이션 고정 | ✅ 핵심 개선 |
| P2 | 맵의 선택에 정보와 대가가 없음 | ❌ 범위 밖 (분석만) |
| P3 | 스코프 과다 — 두 문서 모두 후반부가 빈칸 | ✅ 스코프 관리로 해결 |

### P0 상세

- **전투 문서**: 실제 게임은 덱 8장 → 손패 4장 순환이었으나 문서에 없음. 문서만 읽으면 "마나로 상시 난사"하는 게임으로 읽힘
- **맵 문서**: 생성 규칙은 사각 타일 + 상하좌우 4방향인데, 같은 문서의 생성 예시와 실제 구현은 **육각 타일**

### P1 상세

블루아카이브의 코스트 + 손패 구조를 참조하되 **무작위 추첨 대신 결정론적 순환**(사용 카드는 덱 맨 아래로)을 택했고, **쿨타임도 없었음**. 그 결과:

- 다음 카드를 완전히 예측 가능 → 최적 로테이션이 계산 가능
- 캐스팅 바 3색(초록/주황/빨강)을 읽어도 대응 수단이 없음
- → 플레이어가 자기 손패만 보고 적을 보지 않게 됨

### 이번 재설계의 핵심

> 결정론적 순환을 무작위로 되돌리지 않는다. 대신 **적의 캐스팅에 대응 수단(차단 / 방어도)을 부여**하여 최적 로테이션을 깨뜨리고, **"필요한 카드를 끌어오기 위해 코스트를 지불한다"**는 결정을 만든다.

## 작성 원칙 6가지

**1. 판정 기준은 하나입니다.**
> 이 문서를 처음 보는 프로그래머에게 건넸을 때, 나에게 한 번도 안 물어보고 같은 게임을 만들 수 있는가.

**2. 용어를 먼저 정의합니다.** (P0 재발 방지)
1차 때 "손패가 4개인지 8개인지 모호"했던 문제가 있었습니다. 02 문서 §0 용어표를 반드시 먼저 채우세요.

**3. 모호어 금지.** 아래 단어가 보이면 아직 안 정해진 것입니다.
`적절히` `자연스럽게` `약간` `충분히` `빠르게` `느리게` `강력한` `적당한` `어느 정도` `등등`

**4. 분량의 60%는 표입니다.** 산문은 각 섹션 앞의 "왜 이렇게 설계했는가" 2~3문단뿐입니다.

**5. 숫자에는 항상 근거를 답니다.** "근거/의도" 칸을 절대 비우지 마세요.

**6. 변경은 지우지 말고 취소선 + 변경 이력에 기록합니다.** ← **P0에 대한 직접적인 대답입니다.**
